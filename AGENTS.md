## 1. Operative Rules (Mandatory Every Session)

1. **Never run `uv` in this repo** (`uv run`, `uv sync`, `uv add`): with ComfyUI's venv active, `uv` has emptied `.venv` and dirtied `uv.lock`. Run every script with ComfyUI's venv Python directly:
   ```bash
   COMFY="$(cd ../.. && pwd)" && "$COMFY/.venv/bin/python" <script.py>
   ```
   In Antigravity (`agy`), each `run_command` spawns a fresh subshell (`cd` and `export` do not persist across calls): export `PY` and `$H3_*` at the top of each `run_command` ([`docs/wiki/ops/comfy_notes.md`](docs/wiki/ops/comfy_notes.md)). In inline Python or standalone scripts, call `bench/_lib/__init__.py::bootstrap` before `import comfy` so root [`nodes.py`](nodes.py) never shadows ComfyUI's `nodes.py`.
2. **Use `$H3_INPUT_DIR` and `$H3_OUTPUT_DIR` (`$H3_OUTPUT_DIR/Video`), never share names, mount paths, home paths, or owner names** ([`bench/check_no_owner_paths.py`](bench/check_no_owner_paths.py)). All tracked paths must be repo-relative. Note the **server-flag split** ([`docs/wiki/ops/comfy_notes.md`](docs/wiki/ops/comfy_notes.md)): ComfyUI (`:8188`) resolves inputs/outputs solely from `--input-directory` / `--output-directory` in `<comfy>/start.sh`, whereas `bench/` tools read `$H3_INPUT_DIR`, `$H3_OUTPUT_DIR`, `$H3_MODEL_STORE`, and `$H3_CAPTURE_ROOT`.
3. **The shared tree.** Run `git status` before editing, verify explicit pathspecs with [`bench/check_commit_ready.py`](bench/check_commit_ready.py), and commit promptly with `git commit -F <msg> -- <paths>`. Never run bare `git add`, `git commit -a`, bare `git commit`, `--amend`, or `git push`. The one exception is `git add -- <new_file>` for a brand-new file you created (so [`bench/build_index.py`](bench/build_index.py) indexes it). A file holding a peer's uncommitted hunk is theirs to commit. Subagents never run git in the shared tree; isolate worker checkouts at `../../h3_worktrees/<branch>` (never inside `custom_nodes/`). Normal commits do not touch `CHANGELOG.md` ([`changelog.d/README.md`](changelog.d/README.md)).
4. **Nothing patches ComfyUI core; never hand-edit generated files.** Shipped API graphs (`workflows/**/*.json`) are generated by [`workflows/build_workflows.py`](workflows/build_workflows.py) from [`workflows/h3_config.py`](workflows/h3_config.py); [`INDEX.md`](INDEX.md), [`bench/INDEX.md`](bench/INDEX.md), [`bench/results/INDEX.md`](bench/results/INDEX.md), and [`workflows/INDEX.md`](workflows/INDEX.md) are generated by [`bench/build_index.py`](bench/build_index.py).
5. **Node schema & widget stability ([`bench/check_node_ids.py`](bench/check_node_ids.py), [`bench/check_literal_widgets.py`](bench/check_literal_widgets.py)).** Never rename a `node_id=`, never insert into `get_node_list` in [`nodes.py`](nodes.py) or into a node's inputs/outputs anywhere except at the **end**, and never use `0` as a mode sentinel on numeric widgets.
6. **Check `:8188` before restarting ComfyUI.** Inspect `ss -ltnp 'sport = :8188'` and `tr '\0' '\n' < /proc/$PID/environ | grep '^H3_'` before stopping the server (`bench/restart_comfy.sh` is disabled; see [`docs/wiki/ops/comfy_notes.md`](docs/wiki/ops/comfy_notes.md)). An `H3_*` key in `/proc/$PID/environ` means an active capture is armed — ask before restarting.
7. **Media inspection (`agy`).** Follow [`.gemini/skills/video-understanding/SKILL.md`](.gemini/skills/video-understanding/SKILL.md): inspect `.1fps.<first>-<last>.mp4` companions, `< 100 MB` `.mp4`, and `.png`/`.jpg` stills with native `read_file` first (`$0` API spend) before using Gemini media helpers.

## 2. H3 Frame, Clock, Mask, & Canvas Rules — Read Before Rendering ([`docs/wiki/core/h3_frame_rules.md`](docs/wiki/core/h3_frame_rules.md))

Before picking a `length`, canvas size, mask node, keyframe/sound-cue frame index, or reference clip, obey these H3 laws (details and symbol citations in [`docs/wiki/core/h3_frame_rules.md`](docs/wiki/core/h3_frame_rules.md), [`h3_rules.py`](h3_rules.py), and [`docs/wiki/core/h3_resolutions.md`](docs/wiki/core/h3_resolutions.md)):

- **Fixed `24 fps` video & `40 Hz` (`25 ms`, `32 kHz / 800` hop) audio clocks (`FRAME_RESCALE = 5/3`)**: Core conditioning nodes have no `fps` input; feeding non-24 fps clips warps DiT 3D RoPE and Qwen3-VL `<T.T seconds>` labels. Always resample to `24.0 fps`.
- **Video VAE `17`-frame independent causal clips & `[1, 4, 4, 4, 4]` latent steps**: Valid video lengths satisfy **`17n + 5`** (`5..362`, `h3_rules.py::snap_length`) -> **`5n + 2` video latent steps**. Steps `0, 5, 10, ...` (`frames 0, 17, 34, ...`) are `1`-frame standalone clip starts; steps `1..4` pack `4` pixel frames per step across `32x32` px DiT spatial patches (`16` VAE x `2` patchify). Masks and inpaint operate per `(latent_step, 32x32)` token — a mask cannot toggle inside a `4`-frame step, and all active steps attend bidirectionally across the DiT window.
- **Dual-clock alignment (`39 + 51m`: `39, 90, 141, 192, 243, 294, 345`; `h3_rules.py::on_both_clocks`)**: These 7 lengths are the **only** grids where `17n + 5` video clips and `40 Hz` (`5/3`) audio tokens both land on exact integers (`frames % 3 == 0`). Off-grid `17n + 5` lengths (`22, 124, 362`, etc.) drift by `±1/3` audio token (`8.33 ms`) at the tail (`loop_plan.py::stands_alone` allows them only for single-window renders with no seam). **All chained loops (`h3_rules.py::chain_lengths`: `141..345`, contexts `39` or `90`), `audio_freeze_song` multi-window runs, and every `masked_v2v` load MUST stay on `on_both_clocks`** (`LONG_WINDOW = 345` vs. standalone `LONG_LENGTH = 362`).
- **Never wire stock `SetLatentNoiseMask` onto H3 AV latents**: It writes a flat mask tensor instead of `NestedTensor(video, audio)`, causing the sampler to pad `1`s onto audio (silently regenerating the soundtrack) and trilinearly subsampling masks across `4`-frame steps.
- **Timeline keyframes, `3`-frame audio cues, & `<Video N>` references**:
  - `MiniMaxH3GuideLatent` pins `t >= 0` (`< 5` frames -> `1` frame; `>= 5` frames snaps **down** to `17k + 5`).
  - `MiniMaxH3SoundCues` snaps cues to **`3`-frame (`125 ms`)** multiples (exact `5` audio tokens) and refuses/merges overlapping `cond_audio` RoPE spans (`guide_latent.py::validate_audio_keyframe_spans`).
  - `<Video N>` / `<Picture N>` references sit at `t < 0`: reference clips snap **down** to `17n + 5` (`>= 22` frames for `release` policy), Qwen3-VL samples `<Video N>` at **`2 fps` pairs** (`frames 0, 12, 24, 36, ...`), and `MiniMaxH3ReleaseReferences` (`video_end_percent = 0.33` / `audio_end_percent = 0.33` on 6-step Pika) drops synthetic scaffolding once `shift=12` crosses unshifted midpoint `b = 0.50`.
- **Single-frame (`length = 1`) image exception (`h3_rules.py::SINGLE_FRAME`)**: `length = 1` bypasses `17n + 5` and video duration bounds (`MiniMax-H3-Image`, `P-H3-Image`, Pika `single_frame=True`). `MiniMax-H3-Image` enforces a `4.0 MP` generation floor (+ `MiniMaxH3ImageDownscale` for smaller targets) and uses `PH3_IMAGE_VAE` by default; `P-H3-Image` clamps canvas and `image_1` to `[4 MP, 8 MP]`.
- **Spatial canvas & `int32` QKV threshold**: Trained family uses `768` short edge, `1344x768` (`7:4`, not `16:9`) area cap, `32`-px multiples (`MiniMaxH3Resolution`). Sequences past **`99,864` packed tokens** (`>= 328` frames at `1344x768`, fewer with refs) overflow signed 32-bit fused-QKV strides and require `int64`-safe / rotated attention (`comfy kitchen attention`, `MiniMaxH3SageAttention` fork, or `MiniMaxH3Sol`; KJNodes' `MiniMaxH3TokenCounter` misreports this threshold by `3x` at `299,593`).
