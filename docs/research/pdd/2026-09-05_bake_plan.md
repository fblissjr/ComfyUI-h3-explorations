## 1. What the bake produces

Two files that only load as a pair:

- **A baked checkpoint.** The shipped pruned `int8_convrot` checkpoint with
  its int8 backbone weights replaced by `quantise(W_release + delta)`, every
  other key copied byte for byte. Same layout, same size as the shipped file
  (`ls -lL models/diffusion_models/minimax_h3_fl2va_pruned_int8_convrot.safetensors`).
- **A stripped sidecar.** The converted PDD sidecar with its backbone removed,
  carrying the refiner patch, the baked adaln diffs, the head bank, the
  tables, and a probe cut from the baked checkpoint so the node refuses every
  other pairing. `bench/convert_pdd_lora.py --omit-backbone --baked
  <checkpoint> --baked-strength 1.0` emits it (converter version 3).

What the pair pins is backbone strength and nothing else; the trace is in
`h3_pdd.md`. One baked checkpoint serves every step count.

## 2. Preconditions, all met on 2026-09-05

- **The sidecar contract is built and its two audited gaps are closed.**
  Codex's 2026-09-03 audit found the probe passed any distance and the
  population was derived from the input; commit `e38655d` made the probe int8
  codes and fp32 row scales from the paired checkpoint under exact equality,
  and the population comes from `vendor_config.transformer_depth()`.
  `bench/check_pdd_sidecar_contract.py` exits 0 on the current tree, run
  with the card masked. A note elsewhere that the gaps "come first" predates
  this check and is superseded by it.
- **The release weights are on local NVMe**, in diffusers layout, thirteen
  shards per partition under `<release>/FL2VA/transformer` and
  `<release>/Ref2VA/transformer`, with `model.safetensors.index.json`
  mapping each key to its shard. The keys are already ComfyUI-named
  (`blocks.N.attn.qkv_proj.weight`), so the mapping work is the per-head
  interleave and the rotation, not renaming. No NAS dependency.
- **The quantiser is importable.**
  `comfy_kitchen.backends.eager.quantization.quantize_int8_convrot_weight`,
  the same function `bench/measure_bake_realisation.py` used on 2026-08-31.
- **Disk.** One checkpoint's worth per LoRA per strength on the root volume
  (`df -h /`); bake-to-temp then rename on the same filesystem, so no second
  copy.

## 3. Pieces to lift, not rewrite

re-derive them.

| operation | where it already lives |
|---|---|
| the bake arithmetic, `Q_rtn(hf_to_comfy(W_release) + d)` | `bench/measure_bake_realisation.py`, the `bake_rtn` arm, run over all 200 int8 modules on 2026-08-31 |
| release-to-ComfyUI weight mapping (qkv interleave, rotation) | `bench/analyze_quant_delta.py::hf_to_comfy` |
| the shipped quantisation reproduced to the format floor | `bench/measure_merge_rounding_regimes.py::requant_kitchen` |
| streaming writer for a modified int8 DiT | `bench/build_hybrid.py::write` |

| population and identity checks | `bench/check_pdd_sidecar_contract.py`, `pdd_lora.py::check_backbone_identity`, `check_stripped_targets` |

## 4. The script, `bench/bake_pdd_checkpoint.py`

CPU only. Run with `CUDA_VISIBLE_DEVICES=` like every check
(`docs/checks.md`, "Running them"); the server may be holding the card.

1. **Read the recipe off the template.** For each int8 module in the shipped
   pruned checkpoint, read group size and rotation parameters from its
   `comfy_quant` descriptor. The population is asserted against
   `vendor_config.transformer_depth()`, not counted off the input, the same
   rule the converter follows; a short source must not define its own
   expected size.
2. **Per module, streamed.** Open the release shard the index names, take the
   slice, map it with `hf_to_comfy`, add the sidecar's delta at the bake
   strength, quantise with round-to-nearest, write `weight`, `weight_scale`,
   and the copied `comfy_quant`. Free the module before the next.
3. **Copy everything else byte for byte** from the shipped checkpoint: the
   adaln curve weights and `adaln_t_table`, norms, the bf16 refiner, patch
   projections, the final layer. There is no adaln pruning to reproduce; the
   template already carries it. **The bake touches exactly the int8
   backbone modules and nothing else** (review point, read from
   `bench/convert_pdd_lora.py::strip_backbone` and
   `pdd_lora.py::check_stripped_targets`): the stripped sidecar keeps the
   token-refiner LoRA tensors and applies them onto the bf16 refiner at
   run time, and the node expects exactly the release's refiner count from
   a stripped file. So the refiner is copied through unbaked, on purpose,
   and the next reader need not re-derive it.
4. **Stamp metadata the shipped file lacks** (its header metadata is empty):
   release shard hashes, sidecar hash, bake strength, rounding regime, group
   size, the bake commit, the date, and the partition. The inventory page
   reads these.
5. **Bake to a temp path, reopen from disk, verify, then rename.** Reopened
   because the artifact on disk is the thing under test, not the tensors in
   memory: assert exactly the int8 population was written (200 modules, not
   50 blocks; `_shape_check`'s rule, after this lane once shipped a file that
   dropped a kind silently), dequantise a sample of modules and check the
   error against `W_release + d` sits at the shipped checkpoint's own level,
   and record wall time and peak RSS in the result file.
6. **Cut the stripped sidecar against the reopened file**, then verify the
   three refusals fire on a loaded model: full sidecar on the bake refused,
   stripped sidecar on the base refused, stripped sidecar on the bake loads
   and matches no backbone target. Publish the pair together or not at all.

**Rounding regime: round-to-nearest from the release, at strength 1.0**, the
arm `2026-08-31_bake_realisation.json` measured. The regime is part of the
number and is stamped in the metadata. Settled on review: stochastic
rounding exists to keep a small delta alive under a merge onto an existing
grid, and a bake quantises the sum fresh with no small delta to protect;
`bench/results/2026-08-31_merge_rounding_regimes.json` has stochastic worse
on stored error on every module at equal realisation, and deterministic
rounding is what makes the identity control below possible.

**Order of first runs, from the review.**

1. **Strength-zero identity control, one module.** Quantise one module's
   release weight with NO delta through the exact pipeline (`hf_to_comfy`,
   the rotation, `gs` off `comfy_quant`, round-to-nearest) and compare int8
   codes AND fp32 row scales bit for bit against the shipped file. The
   regimes record has the shipped and baked errors agreeing to many digits,
   which is error magnitude, not code identity. Codes matching proves the
   whole pipeline independent of the LoRA; codes not matching names the
   vendor's regime before anything is written.
   **Run 2026-09-05, block 0
   (`bench/results/2026-09-05_bake_identity_control_block0.json`): not bit
   identical, and the same regime.** Every module differs from the shipped
   file on a handful of codes out of tens of millions, each by exactly one
   step, with scales differing at float32-ulp level and the error against
   the release equal to the shipped file's within float epsilon. The
   alternatives were run on two modules the same hour and ruled out:
   stochastic rounding and every bf16 path (bf16 input, bf16 rotation, bf16
   row-wise) differ on millions of codes; an fp64 rotation lands the same
   handful. So the vendor quantised in fp32 with round-to-nearest, on
   another device or accumulation order, and the differing codes are
   rounding ties. The pass criterion was made explicit on the render lane's
   review and lives as `bench/bake_pdd_checkpoint.py::TIES_CRITERION` with
   provenance "measured, ties"; a strict bit-identity verdict would have
   read as a regime mismatch. Cross-backend: the 2026-08-31 regimes record
   has eager and CUDA round-to-nearest agreeing exactly, so the ties are
   between the vendor's run and ours, not between our backends.
2. **The same control across all 200 modules**, as the dry pass, reading
   only. **Run 2026-09-05
   (`bench/results/2026-09-05_bake_identity_control.json`): same regime on
   every module of every kind, per-kind summaries in the record, one
   module bit-identical.** The risk-table row about a re-rounded base
   resolves as "the same draw except at ties"; no strength-zero control
   checkpoint is needed.
3. **One block at strength 1.0 to scratch**: bake, reopen, dequantise,
   compare against `W_release + d`. **Run 2026-09-05
   (`bench/results/2026-09-05_bake_scratch_block0.json`): written,
   reopened, four int8 modules by kind, error against the target at the
   shipped file's own level on each.** The writer, the header planning and
   the reopen check are exercised by this run.
4. **The full bake**, then the sidecar cut, then the CPU-only cases the
   contract check can run against the reopened artifact: probe equality,
   full sidecar on the bake refused, stripped on the base refused, and the
   metadata fields the node reads (`h3_pdd_backbone_strength_baked`,
   `h3_pdd_baked_checkpoint`). **Run 2026-09-05, server down, card empty
   (`bench/results/2026-09-05_bake_fl2va_full.json`): every int8 module of
   every kind written, the reopened file's error against its target at the
   shipped level on all 200, the release shards and the sidecar hashed into
   the metadata, renamed from `.partial` only after that.** The stripped
   sidecar was cut against the reopened file with the same `--pdd`,
   `--base` and `--pruned` the shipped fl2va sidecar records in its own
   metadata. `bench/check_pdd_sidecar_contract.py` gained the real pair as
   cases (probe of the stripped file equals the bake and not the base, its
   base probe the reverse, the full sidecar's probe not the bake, the four
   identity decisions, the bake's int8 population and metadata) and is
   green on them.
5. **The node's stripped `execute` path against the real pair**, the one
   thing the contract check's docstring recorded as never run end to end.
   **Run 2026-09-05 on a loaded model, CPU only, with ComfyUI's `--cpu`
   flag set before its model manager imports
   (`bench/exercise_pdd_stripped_path.py`, log in
   `bench/results/2026-09-05_bake_node_stripped_path.txt`): stripped on the
   base refused naming the unbaked base, stripped on its bake loads, full
   on the bake refused as a double apply.** A render is the render lane's.

**Memory, and the writer.** The live server holds most of host memory while
the DiT is staged (`free -g` at the time). `bench/build_hybrid.py::write`
copies raw bytes from source files, so it is the format authority, not the
writer: the bake needs a writer that emits computed tensors one module at a
time with the header precomputed from the shipped file's shapes and dtypes,
which are unchanged, so the offsets are the shipped file's plus the metadata
length. The script states a peak-RSS budget and refuses to start below it;
the 2026-08-25 bridge load took ComfyUI down, and the owner renders on this
host. No GPU, `CUDA_VISIBLE_DEVICES=` throughout.

**Runtime and memory are in the records, not here.** Each result file
carries `wall_s` and `peak_rss_gb` for its own run; the 200-module control
and the one-block bake are the two measured so far, and the full bake's
record will carry its own. The 2026-08-31 records carry no wall time.

## 6. The first render, and what it tests

Merged PDD8 against baked PDD8 at 8 evaluations, the trained width, same
scene and seed, under sage alone per the 2026-09-04 ladder rule, blinded
through `bench/blind_batch.py` with the singles scored for audio, on a
regenerated score page. One pair is a screen, not a verdict
([`../../eval_comparison.md`](../../eval_comparison.md)). It is also the
test of the roadmap's bake hypothesis: that the defects named blind on the
shipped PDD8 rung are the kind a requantised merge produces. If the baked arm
shows the same defects, the merge is not their cause and the hypothesis is
closed.

## 9. Where this goes wrong, and the control for each

Written before the script, from this lane's own history; each row names
the control that would catch it rather than the care that would avoid it.

| risk | how it shows | control |
|---|---|---|
| the delta is computed with a different scale than the node applies (alpha over rank, the fused qkv rank, strength) | a baked file that is a valid checkpoint at the wrong strength; the identity probe cannot tell strength from the codes alone | compute the delta through the same function the node uses at the call (`pdd_lora.py::split_unmerged` builds `a`, `b` with strength, alpha and rank folded), never a fresh formula; compare one module's `delta` against the node's at load |
| the release-to-ComfyUI mapping is wrong for one module kind (qkv per-head interleave, the rotation, fc1's SwiGLU halves) | renders that look plausibly wrong, no error | a strength-zero bake of one block must dequantise to the shipped checkpoint's own weight within the requantisation noise, kind by kind; `2026-08-31_bake_realisation.json` already ran this mapping over all 200 modules and is the reference for what the residual should be |
| the quantiser's rotation or group size differs from the descriptor the kernel reads | the int8 kernel dequantises with the wrong rotation and the render is garbage, silently | read `gs` and the rotation parameters off each module's `comfy_quant`; after the bake, dequantise through ComfyUI's own path with the copied descriptor and compare to `W_release + d` |
| a module kind dropped from the write | a valid-looking file missing 50 modules; this lane shipped one | assert the population by kind against `vendor_config.transformer_depth()`, four kinds times the depth, on the reopened file |
| the baked base is a different rounding draw from the shipped base, so the merged-versus-baked pair differs in two things | any difference reads as the bake's, when part of it is the base re-rounded | the strength-zero identity control in section 4 settles it before anything is written. **Resolved 2026-09-05: same regime, ties only** (`bench/results/2026-09-05_bake_identity_control.json`), so the baked base is the shipped base except at a handful of one-step rounding ties per module, and no control checkpoint is needed |
| the node's stripped path has never run end to end | a refusal message with a bug, or a stripped load that matches a backbone target | the refusal tests in section 4 step 6 run on a loaded model with the card masked; host memory is the constraint while the server holds the DiT, so schedule them when the server is down |
| the merged arm is an old clip from a different core | a cross-regime pair; the ladder's clips already predate one pull | render both arms fresh in one session on one server, cold cache, and record the server's commit in the manifest |
| the server is armed when the pair renders | timings void, and a probe render's clip is a valid sample only because that was measured once | read the port owner's environment for `H3_*` keys before queueing (`docs/comfy_notes.md`) |
| the source sidecar or the upstream alibaba-pai file changed in place | a bake of a file nobody can name | stamp the sidecar hash and the upstream source hash in the baked file's metadata; the upstream weights and code are on this box under the alibaba-pai download and `docs/pdd_artifacts.md` records their fingerprints |
| a new checkpoint name that no check knows | `check_model_files.py` red, or worse, a graph naming a file it cannot open | register the name before the generator entry; rebuild, never hand-edit |
| the render's first step is silent for minutes | the render gets killed as hung | say how long the silence lasts before queueing, per the standing rule |
| the bake and the live server compete for host memory | ComfyUI goes down mid-render, as the 2026-08-25 bridge load did | one computed module resident at a time with a precomputed header; the script states a peak-RSS budget, reads `free` and refuses to start below it; the card masked so no CUDA context is opened |
| the identity control passes on one module and fails on a kind it did not sample | a full bake that is right for three kinds | the control runs read-only across all 200 modules before the one-block write, and reports per kind |

## 10. Not this bake

**The larryvrh turbo LoRA is a second bake, conditional.** The arithmetic on
the int8 backbone is identical, but that file's adaln update needs either its
own node's runtime injection or a converter that ingests a plain LoRA and
bakes adaln into the curve basis as ours does for PDD. It earns a bake only
if its rung on the ladder passes the owner's eye under sage; the reading of
that node and what generalises from it is in
[`../../h3_pdd.md`](../../h3_pdd.md), the 2026-09-05 section. Ref2VA's PDD
bake is the same script pointed at the other partition, after fl2va's pair
has rendered.
