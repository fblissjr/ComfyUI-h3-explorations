## What Was Researched & Found on 2026-11-05

1. **Zero-Template Contrastive Pair Authoring**:
   - Earlier LLM-authored pairs (`7593e65f`) used rigid sentence templates, repeated verbatim `b_span` strings across `Pairs 1–8`, stuffed 5-attribute baseline strings into `Prompt A` across 5 vectors (causing `+0.42..+0.79` cross-vector cosine overlap), and placed target nouns (`head`, `gravity`) inside `Prompt A` or the shared prefix so $B - A$ canceled the target noun out of the vector.
   - Replacing few-shot templates with a structural single-clause substitution rule (`Prompt B` alone names the target body part or phenomenon; `Prompt A` describes the single baseline axis holistically; zero rate adverbs like `slowly`/`gradually`) dropped `cos(head_swell, zero_gravity)` from `+0.62` to `+0.26..+0.30` (`962c8985`, `db821224`).
   - *(Updated 2026-11-06 in [`docs/wiki/system_prompts/h3_control_vector_system_prompt.md`](../../wiki/system_prompts/h3_control_vector_system_prompt.md))*: Aligned `<d>[English] ...</d>` with `vendor_guides/base_en.md` §4.4, replaced uniform post-dialogue indoor occupational scenes with a **Stratified 10-Pair Scene Matrix** (mixing speaking, silent human, two-person, and non-human shots across `5` interior + `5` exterior settings and varied syntactic clause positions under `--pooling diff_span`), enforced `10/10` unique `a_span` and `b_span` clauses, and added optional `### Hold Pairs` (`[[hold]]`).

## Converting LLM Markdown Output to `.toml` (`bench/control_vectors.py from-md`)

Once the LLM returns its Markdown response (`### Test Scene Prompt` + `#### Pair 1..10`), convert and validate it directly into a `.toml` pair file using [`bench/control_vectors.py`](../../../bench/control_vectors.py)` from-md` (alias `import-md`, backed by [`control_vectors.py::parse_markdown_pairs`](../../../control_vectors.py#L470-L610) and [`control_vectors.py::write_markdown_to_toml`](../../../control_vectors.py#L627-L797)):

```bash
$PY bench/control_vectors.py from-md path/to/llm_output.md \
    --out prompt_bank/control_vectors/my_vector.toml \
    --quality "Target visual/physical/acoustic transformation vs. unsteered baseline" \
    --a-side "Unsteered baseline description" \
    --b-side "Steered target description" \
    --test-prompt-out path/to/my_vector_test_prompt.txt \
    --overwrite
```

- **Automatic fence unwrapping & mode detection**: Unwraps any outer ```` ```text ```` or ```` ```markdown ```` code fence, extracts `### Test Scene Prompt` (saving it as `# Test Scene Prompt` comments at the top of the `.toml` and optionally to `--test-prompt-out <file.txt>`), auto-detects `mode = "ref2va"` if `subject_definitions:` is present (else `mode = "t2va"`, overridable with `--mode`), auto-fills `--a-side`, `--b-side`, and `--quality` from Pair 1's differing clause when omitted, and verifies all 10 pairs through `differing_span` + `load_pairs` before writing.

## Why Initial Physical-Action Renders (`25..30`) Failed and How We Got Them to Work (`31..40`)

When testing the single-clause end-of-section physical transformations ([`head_swell.toml`](../../../prompt_bank/control_vectors/head_swell.toml) on `t2va` and [`zero_gravity.toml`](../../../prompt_bank/control_vectors/zero_gravity.toml) on `ref2va`) at `1344x768x141` (`5.88s` at `24 fps`) under Pika H3 Flex (`6`-step `lcm`), our initial renders (`arms 25..30` at `s = +2.50, +4.00`) showed only subtle extra tabletop props or slight cranial widening rather than unmistakable mid-air levitation or balloon-scale head expansion.

Systematic ablation across `arms 31..40` ([`bench/results/2026-11-05_control_vectors_pika_and_ref2va.md`](../../../bench/results/2026-11-05_control_vectors_pika_and_ref2va.md)) isolated and solved all four root causes:

1. **Post-Dialogue Timeline Budget (`1.5s` Speech + `4.3s` Effect Window vs. Multi-Clause Setup + Static-Frame Tail)**:
   - Because the changed clause in every pair of `head_swell.toml` and `zero_gravity.toml` sits at the **end** of `integrated_multimodal_description:` **after** `<d>...</d>`, a longer dialogue line (`<d>I think we should order another slice of pie.</d>` in `arms 25..27`) or a multi-sentence pre-speech setup (`arms 28..30`, `<d>Hi, how are you?</d>`) reduces the post-speech window inside a `5.88s` (`141`-frame) render.
   - **Fix**: Keep the test prompt's `<d>...</d>` line to `1–5` words (`<d>Morning!</d>`, `<d>Another pie?</d>`, finishing at `~1.2–1.5s`) and keep the pre-speech setup concise so a `141`-frame render has `4.3–4.6s` of post-dialogue visual runtime (`arms 31..40`).
2. **Omitting Trailing Static-Frame / Fixed-Pose Clauses in the Base Prompt**:
   - In `arms 25..27`, the `ref2va` base prompt ended with `"before closing his mouth naturally as his gaze remains fixed forward"` (and `"The camera holds a static medium shot"`), and in `arms 28..30` the `t2va` prompt ended with `"while the camera holds a steady static frame on his upper body"`—occupying the exact post-speech syntactic slot where the control vector's effect occurs.
   - **Fix**: End the unsteered `Test Scene Prompt` cleanly after the speaker's dialogue and lip-closure (`"before settling his lips."` / `"His speech finishes cleanly and his mouth closes smoothly into a calm smile."`), without appending trailing static-frame or Pole-A grounding clauses.
3. **`2.12x–8.21x` Prefix & Suffix Dilution Under `scene_text` Pooling vs. `--pooling from_first_diff` and `--pooling diff_span`**:
   - Because single-clause `.toml` pairs share ~85–110 identical scene-setup tokens before the 8–12 word diff clause plus ~30–40 identical tokens in `overall_soundscape:` and `non_diegetic_music:`, mean-pooling `token_refiner` over all `scene_text` tokens averages ~90% near-zero shared tokens with ~10% changed clause tokens (`raw_norm = 10.35` on `head_swell` and `10.65` on `zero_gravity`).
   - **Fix**: Extract single-clause vectors with either:
     - **`--pooling diff_span`** (`[first_diff:end_diff]`, stripping both the shared prefix `[:first_diff]` and the shared suffix `[end_diff:]` including `overall_soundscape:` and `non_diegetic_music:` so only the `6–15` changed clause tokens are pooled: `raw_norm = 85.01` on `head_swell_ds` and `raw_norm = 85.13` on `zero_gravity_ds`, **`~8.0x–8.2x` stronger**, running at **`s = +0.6..+1.0`**), or
     - **`--pooling from_first_diff`** (`[first_diff:]`, stripping the shared prefix `[:first_diff]`: `raw_norm = 23.57` on `head_swell_ffd`, **`2.28x` stronger**, `cos = 0.9427`; `raw_norm = 22.62` on `zero_gravity_ffd`, **`2.12x` stronger**, `cos = 0.9403`, running at **`s = +3.0..+3.5`** in `arms 39, 40`), or
     - Scale `scene_text`-pooled vectors to norm-matched **`s = +6.5..+8.0`** (`arms 32..33, 35..36`).
4. **On-Manifold Physical Reconciliation vs. Unassisted Mid-Air Levitation (`from_first_diff`)**:
   - Because `apply_post_refiner` broadcasts the 1D `[5376]` vector uniformly across all non-vision tokens, at `scene_text` `s = +6.5..+8.0` (`arms 32..33`) the DiT + Pika LoRA reconciles upward object trajectories with its real-world physical prior by having `<Subject 1>` reach out and lift the mug, spoon, and fork to eye level.
   - Extracting with **`--pooling from_first_diff`** removes the 70% shared-prefix noise: at **`s = +3.50` (`40_ref2va_diner_zero_grav_ffd_s3p5`)**, a ceramic dinner plate, a coffee mug, and a silver fork **levitate unassisted in mid-air** above the diner booth across `f = 42..140` while `<Subject 1>`'s hands hold two other utensils separately. On `head_swell`, both `scene_text` `s = +8.00` (`36`) and `from_first_diff` `s = +3.50` (`39`) match the explicit Pole-B text positive control (`34`) with a **`~1.70x` screen-space cranial ballooning** (`25.8% -> 43.9%` of frame width) and a synthesized pressurized steam-inflation hiss.

## How to Extract and Run Control Vectors for `t2va`, Dual-Vector `t2va`, and `ref2va`

### 1. Shipped API Workflows in `workflows/`
- **Single-Vector `t2va` (Pika 6-Step LCM)**: [`workflows/h3_text_to_video_pika_control_vector_api.json`](../../../workflows/h3_text_to_video_pika_control_vector_api.json)
  - Wires `MiniMaxH3LoRABranch (18, pika_h3_flex_fl2va_svd995_bf16.safetensors) -> MiniMaxH3SigmaShift (19, shift_video=12.0, shift_audio=3.0) -> ModelAttentionBackend (58) -> MiniMaxH3Sol (21) -> MiniMaxH3ApplyControlVectors (115) -> BasicGuider (9)`.
- **Dual Chained Control Vectors on `t2va` (Pika 6-Step LCM)**: [`workflows/h3_text_to_video_pika_dual_control_vectors_api.json`](../../../workflows/h3_text_to_video_pika_dual_control_vectors_api.json)
  - Chains two `MiniMaxH3ApplyControlVectors` nodes in series (`21 -> 115 (film_16mm_1974, strength=1.8) -> 125 (chaos_panic, strength=2.2) -> BasicGuider (9)`), allowing independent `mode` (`add`, `add_norm_matched`, `hold`, `project_out`, `amplify`), `mask` (`non_vision`, `scene_only`, `after_dialogue`, `description_only`, `soundscape_only`, `all_rows`), and `start_percent`/`end_percent` step windows per vector (`arms 37, 38`).
- **Character-Reference `ref2va` Control Vector (Pika 6-Step LCM)**: [`workflows/h3_image_ref_plus_text_to_video_pika_control_vector_api.json`](../../../workflows/h3_image_ref_plus_text_to_video_pika_control_vector_api.json)
  - Wires `LoadImage (12) -> MiniMaxH3ReferenceConditioning (10, mode="r2v")` and `MiniMaxH3LoRABranch (18, pika_h3_flex_ref2va_svd995_bf16.safetensors) -> 19 -> 58 -> 21 -> MiniMaxH3ApplyControlVectors (115, mask="non_vision") -> BasicGuider (9)`.

### 2. Extracting `t2va` (`fl2va`) and `ref2va` Control Vectors (`.safetensors` + Companion `.md` Sidecars)
Because `fl2va` (`minimax_h3_fl2va_pruned_int8_convrot.safetensors`) and `ref2va` (`minimax_h3_ref2va_pruned_int8_convrot.safetensors`) have distinct `condition_proj` + `token_refiner` weights, extract the vector against the matching model family and LoRA (`python bench/control_vectors.py build <file>` builds both families automatically with default `--pooling diff_span`). Every `build` or `make` run writes both `<stem>.safetensors` and a human-readable `<stem>.md` sidecar documenting how it was built (`.safetensors` filename, `pooling` mode, `family`, `recipe`, `raw_norm`, recommended ComfyUI `strength` range, quality report, and per-pair `[first_diff:end_diff]` token spans):

```bash
# A. Recommended one-shot dual-family build (default --pooling diff_span, run at strength = 0.6..1.5 or 1.0 with add_norm_matched):
$PY bench/control_vectors.py build prompt_bank/control_vectors/film_16mm_1974.toml --overwrite

# B. Explicit single-family make with --pooling diff_span (default, strips shared prefix [:first_diff] and shared suffix [end_diff:]):
$PY bench/control_vectors.py make \
    prompt_bank/control_vectors/head_swell.toml \
    --unet minimax_h3_fl2va_pruned_int8_convrot.safetensors \
    --lora pika_h3_flex_fl2va_svd995_bf16.safetensors:1.0 \
    --pooling diff_span \
    --device default --refiner-device cuda \
    --include-encoder --overwrite

# C. Single-clause end-of-section physical action on t2va/fl2va (--pooling from_first_diff, run at strength = 3.5):
$PY bench/control_vectors.py make \
    prompt_bank/control_vectors/head_swell.toml \
    --unet minimax_h3_fl2va_pruned_int8_convrot.safetensors \
    --lora pika_h3_flex_fl2va_svd995_bf16.safetensors:1.0 \
    --pooling from_first_diff \
    --device default --refiner-device cuda \
    --include-encoder --overwrite

# D. Single-clause end-of-section physical action on ref2va (--pooling diff_span or --pooling from_first_diff, mask="non_vision"):
$PY bench/control_vectors.py make \
    prompt_bank/control_vectors/zero_gravity.toml \
    --unet minimax_h3_ref2va_pruned_int8_convrot.safetensors \
    --lora pika_h3_flex_ref2va_svd995_bf16.safetensors:1.0 \
    --pooling diff_span \
    --device default --refiner-device cuda \
    --include-encoder --overwrite
```
