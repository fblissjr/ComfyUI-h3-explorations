# Stage table: is ComfyUI's SAM 3.1 code the same computation as Meta's?

Written by the helper session mryolk on 2026-10-07; placed by mregg with the day's corrections folded in. Last updated 2026-10-07. ComfyUI is the checkout at commit b00c6e952; paths with no prefix are in it. Meta's code is the pack's copy `meta_sam3/sam3/` unless a row says `coderef/sam3` (commit 0570b3a). The copy was edited; `meta_sam3/EDITS.diff` lists every difference from upstream, and the ones that matter to a comparison are under "The copy is not upstream" below. The page [`2026-10-07_mryolk.md`](2026-10-07_mryolk.md), beside this table, walks through the same stages in prose and collects the measurements (its section 7).

How to read a verdict. Same (read): both sides were opened and compute the same thing (constants and structure); it is not a proof that the tensors are equal. Same (run): both were also run on equal input and agreed. Different: they differ, and the next column says whether it is a choice (a default, a threshold) or a departure (the computation differs). Not established: the internals were not compared; the row says what was read. Each row ends with the tensor to compare.

## Three differences found first

1. Image range (row 9). Meta's list-of-images route and its image processor feed the trunk `(x/255 - 0.5)/0.5`, so values in -1 to 1 (its video-file route read with OpenCV does not divide by 255 as written, `meta_sam3/sam3/model/io_utils.py:348-365`: read, not run; see the page's 4.4); ComfyUI feeds 0 to 1 and has no normalisation anywhere in its SAM 3 path. Measured at the trunk input.
2. Text-encoder activation (row 3). ComfyUI's config says `quick_gelu`; Meta's text transformer uses exact GELU. Measured: features differ and agree once switched.
3. Object pointer token (row 22). The 3.1 tracker's pointer is token 0 in ComfyUI and the best-quality token in Meta. Real in the code; measured not to be the cause of the track losses seen.

## Not established, and what was read for each

- Trunk internals (row 10): ComfyUI's `ViTDet` in full and Meta's builder constants; not `meta_sam3/sam3/model/vitdet.py`'s blocks, rotary embedding or attention.
- Detector decoder internals (row 12): ComfyUI's decoder in full and Meta's builder; not Meta's `meta_sam3/sam3/model/decoder.py` layer bodies.
- Geometry encoder and mask head (rows 13, 16): structure, plus the one-frame detector run in row 12. Both pixel decoders loop over the feature maps below the last one, so three maps give two upsampling steps on both sides (`comfy/ldm/sam3/detector.py:321-325`, `meta_sam3/sam3/model/maskformer_segmentation.py:220-235`).
- Text-encoder block internals (row 3): Meta's constants and forward; not its residual block body.
- Any one tracker step against Meta from the same seed (rows 19 to 24): only whole-track outcomes were compared (page section 7).

## The order to test them in

1. Tokens (rows 5 to 8): run, equal.
2. Text features before the projection (row 3): run, different by the activation.
3. The projection output (row 4).
4. Trunk input range and trunk output (rows 9, 10): run; range different, trunk alike on equal input to what is read as the float32-against-bfloat16 floor.
5. The three neck outputs (row 11).
6. The 200 boxes, class logits, presence and masks (rows 12 to 16): run on one frame and one phrase, agreeing on confident queries.
7. The refined mask against the raw one (row 18).
8. One tracker step: conditioning output, pointer, memory-attention output, memory maps, object scores (rows 19 to 24).
9. The output mask (row 28).

A mismatch at step 2 or 4 contaminates everything below it, so neutralise it (give Meta's input and Meta's activation to a patched copy of ComfyUI's model) before reading steps 5 and up.
