## 1. What this page is

This page follows one request through ComfyUI's SAM 3.1 nodes in the order things happen: a video and the word "person" in, a mask per frame out. It is for someone who knows ComfyUI and not SAM. Each stage says what goes in, what comes out (shapes and data types), which file does it, and what Meta's own code does at the same point.

Paths with no prefix are in the ComfyUI folder. Paths starting `meta_sam3/`, `coderef/`, `bench/` or `workflows/` are in this repository. [`2026-10-07_mryolk_stage_table.md`](2026-10-07_mryolk_stage_table.md), beside this page, has one row per stage with the lines on both sides and the tensor to compare; this page points at it rather than repeating it.

Every stage carries one verdict. Same: ComfyUI and Meta compute the same thing, shown by running both ("run") or only by reading both ("read"). Different: they differ, as a choice (a default or a threshold) or a departure (the computation itself). Not established: nobody has compared them.

Numbers are either constants read from code, with the file and line beside them, or measurements. The measurements are collected in section 7, each with the probe that produced it.

## 2. The parts in one picture

One checkpoint file holds two models that share one image trunk.

```
phrase --> tokens --> text tower (24 layers) --> text features
                                                      |
frames --> resize to 1008x1008 --> trunk (32 blocks) --+--> necks (3 sets of feature maps)
                                                      |
   detector: encoder, 200 queries, scores, boxes, masks   <- detector neck + text
   tracker:  memory, memory attention, mask decoder       <- tracker necks
```

The detector finds objects that match a phrase on one frame. The tracker follows objects from frame to frame using a memory of earlier frames. It handles 16 objects at a time: objects are packed into groups of 16 slots called buckets, and each bucket is decoded together (the "multiplex"; `comfy/ldm/sam3/tracker.py:32-70, 1152`).

ComfyUI picks the 3.1 tracker when the checkpoint has the key `detector.backbone.vision_backbone.propagation_convs.0.conv_1x1.weight` (`comfy/model_detection.py:1157-1163`).

## 3. Three ways to drive it

1. An image and a phrase: `SAM3_Detect` with a text conditioning. No tracker runs.
2. A video and a phrase: `SAM3_VideoTrack` with a conditioning and no `initial_mask`. The detector looks at the frames, the first detections become the tracked objects, and later detections add objects and refresh tracks.
3. A video and seed masks: `SAM3_VideoTrack` with an `initial_mask` and no conditioning. The masks on the first frame are the objects and the detector never runs. This is the path the masked-video lane uses. With both an `initial_mask` and a conditioning, the seeds start the tracks and the detector also adds and refreshes objects.

| stage | image + phrase | video + phrase | video + seed masks |
|---|---|---|---|
| 4.1 load the file | yes | yes | yes |
| 4.2, 4.3 phrase to text features | yes | yes | no |
| 4.4 frames to model input | yes (bilinear) | yes (bicubic) | yes (bicubic) |
| 4.5, 4.6 trunk and necks | yes | yes | yes |
| 4.7 detector | each image | each detection frame | no |
| 4.8 the detect node's own steps | yes | no | no |
| 4.9 seeding | no | from the first detections | from the given masks, frame 0 only |
| 4.10, 4.11 tracked frames | no | yes | yes |
| 4.12 new objects and refresh | no | yes | no |
| 4.13 output | masks and boxes | packed masks per frame | packed masks per frame |

## 4. Stage by stage

### 4.1 Loading the file

In: one safetensors file in `models/checkpoints`. This setup has two: the pack's float32 repack of Meta's weights (`bench/convert_sam3_checkpoint.py`) and Comfy-Org's float16 release.

Out: from `CheckpointLoaderSimple`, a MODEL (detector and tracker together) and a CLIP (the text tower). Text keys under `detector.backbone.language_backbone.` go to the CLIP side; the small projection from text width 1024 to detector width 256 (`resizer`) stays in the detector.

Where: `comfy/supported_models.py:2456-2507`. At load, `tracker.model.*` is renamed `tracker.*`, per-block rotary tables are dropped (they are recomputed), every fused attention tensor is split into q, k and v, and three decoder key names change (`:2468-2493`). The model class is `comfy/model_base.py:2974-2976`, which builds `SAM3Model` (`comfy/ldm/sam3/detector.py:512-519`). The first supported data type is float16 (`:2458`).

Meta: `meta_sam3/sam3/model_builder.py:662-688` loads a `.pt` and renames `sam3_model.` to `detector.` and `sam2_predictor.` to `tracker.`.

Verdict: same for names and splits (read). The weights are Meta's: Comfy-Org's file equals the pack's cast to float16 in every shared tensor, and the trunk agrees with Meta's on equal input (section 7). Not compared: the pack's repack against Meta's original `.pt`, tensor by tensor.

### 4.2 The phrase becomes tokens

In: the text of a `CLIPTextEncode`, such as `person` or `person:16, hat:2`.

Out: token ids in rows of 32 (start 49406, end 49407, pad 0; `comfy/text_encoders/sam3_clip.py:21, 26`), plus a list of phrases with a detection count each.

Where: `comfy/text_encoders/sam3_clip.py`. `_parse_prompts` (`:30-47`) removes parentheses, splits on commas and reads a trailing `:N` as "at most N detections for this phrase". A single phrase with count 1, including one with no suffix, skips that and goes through ComfyUI's generic tokenizer with the text unchanged (`:51-54`). Several phrases, or a count above 1, are tokenized one by one. The vocabulary is CLIP's (`comfy/sd1_tokenizer/merges.txt`).

Meta: `meta_sam3/sam3/model/tokenizer_ve.py` uses the same merges, cleans text with `ftfy` (not installed here; the copy falls back to a plain Unicode normalisation) and cuts to 32 tokens with the end token last (`:263-264`).

Verdict: same (run) for the tokens: equal on 31 phrase parts at context length 32, and the merge files match. Different, a departure: the count syntax is ComfyUI's own and the model has no such feature; a phrase longer than 30 tokens (32 less the start and end tokens, `comfy/text_encoders/sam3_clip.py:21, 26`) continues in a second row in ComfyUI while Meta cuts it. Non-ASCII text is equal only to Meta's copy, not to upstream.

### 4.3 Tokens become text features

In: token ids [1, 32].

Out: features [1, 32, 1024] with an attention mask; in the detector, the projection to [1, 32, 256] (`comfy/ldm/sam3/detector.py:476`; video `:583-584`).

Where: `SAM3ClipModel` (`comfy/text_encoders/sam3_clip.py:4-21`) is a CLIP text transformer: 24 layers, 16 heads, width 1024, feed-forward 4096, context 32. Its configured activation is `quick_gelu` (`:6`).

Meta: `meta_sam3/sam3/model/text_encoder_ve.py` has the same sizes with an exact GELU activation (`:25, 105, 186`).

Verdict: different, a departure, measured. With the 24 activations switched to exact GELU the features agree to within a hundredth, which is read as float32 against bfloat16; that floor was not measured by itself (section 7). One-word phrases gave the same detections; a describing phrase gave the same number of detections with about half the presence score, at a presence Meta's own detection rule (4.8) would reject, so for such a phrase the activation matters only together with that rule. The text tower computes in float32 on the server's loading path.

### 4.4 Frames become the model's input

In: an IMAGE [B, H, W, 3], float32, values 0 to 1, on the intermediate device (the CPU unless the server runs with `--gpu-only`; `comfy/model_management.py:1267-1271`).

Out: [B, 3, 1008, 1008] in the model's data type on the GPU, values still about 0 to 1 (bicubic overshoots a little).

Where: the detect node resizes with bilinear interpolation (`comfy_extras/nodes_sam3.py:118`); the tracker resizes each frame with bicubic (`comfy/ldm/sam3/tracker.py:207-209`). Both stretch the frame to a square with no crop or padding, and neither smooths when shrinking: `common_upscale` is a plain `torch.nn.functional.interpolate` (`comfy/utils.py:1133`). Nothing changes the value range.

Meta: its code has several loading routes in `meta_sam3/sam3/model/io_utils.py`. The route for a list of images, which is the one the measurements on this page drive, resizes to a 1008 square and maps values to -1 to 1 with `(x/255 - 0.5)/0.5` (`:60-72`; mean and deviation 0.5, `meta_sam3/sam3/model_builder.py:657-658`), and Meta's image processor normalises the same way (`coderef/sam3/sam3/model/sam3_image_processor.py:26`). The other routes were not run for this page. Read, not run: the image-folder and torchcodec routes also scale to 0 to 1 before the mean and deviation, and the route for a video file read with OpenCV, which is the default for a video file (`video_loader_type="cv2"`, `meta_sam3/sam3/model/io_utils.py:41`), casts the frames to float32 and subtracts and divides by 0.5 with no division by 255 (`meta_sam3/sam3/model/io_utils.py:348-365`; the same lines upstream, and not one of the copy's edits). So on that route the values are not in -1 to 1. Every run of Meta's code in this repository so far handed it a list of images. Whether upstream intends the video-file route as written was not looked into, and anyone using the copy as a reference should hand it a list of images. The resize also depends on the route: Pillow bicubic for a list of images (`:61`), torchvision bilinear for an image folder (`:388-391`), OpenCV cubic for a video file, the default (`:333-335`), PyTorch bicubic with torchcodec (`:721-727`). The last two do not smooth either.

Verdict: different, a departure, measured: the trunk receives 0 to 1 in ComfyUI and -1 to 1 on Meta's list-of-images route and from its image processor, on the pack's file and on Comfy-Org's. The patch embedding has no bias (`comfy/ldm/sam3/sam.py:214-220`) and the weights are not rescaled, so nothing absorbs it. The resize kernel is a choice, and not a small one: with the range mapped, ComfyUI's unsmoothed bilinear resize against Meta's Pillow resize moved the trunk's features about four times as far as the equal-input comparison's own difference, on one frame (section 7). How much the range fault costs depends on the frames (section 7).

### 4.5 The trunk

In: [B, 3, 1008, 1008]. Out: [B, 1024, 72, 72].

Where: `comfy/ldm/sam3/sam.py:223-298`. A 14 by 14 convolution with stride 14 cuts the image into 72 by 72 patches. A learned position table (trained on a 24 by 24 grid, tiled) is added, then a layer norm, then 32 blocks of 16-head attention with 2-D rotary positions. Most blocks attend inside 24 by 24 windows; blocks 7, 15, 23 and 31 attend over all 5,184 patches. Every attention call in the SAM code passes `low_precision_attention=False` (`comfy/ldm/sam3/sam.py:43, 182`; `comfy/ldm/sam3/detector.py:57`; `comfy/ldm/sam3/tracker.py:372, 665, 676`), so the 8-bit attention kernel is never used for SAM.

Meta: `meta_sam3/sam3/model_builder.py:55-84`, the same constants.

Verdict: same (run) on equal input, as far as this comparison can say: the same tensor through ComfyUI's trunk and Meta's differs by an amount read as float32 against bfloat16, a floor that was not measured by itself (section 7). Block internals are read, not compared line by line.

### 4.6 The necks

In: the trunk output. Out: three sets of three feature maps, [B, 256, 288, 288], [B, 256, 144, 144] and [B, 256, 72, 72], each with a sine position map. The sets are a detector set, a tracker "propagation" set and a tracker "interactive" set: separate weights on the same trunk output.

Where: `comfy/ldm/sam3/sam.py:301-330, 377-425`. The detect node computes the detector and propagation sets (`comfy/ldm/sam3/detector.py:406-413`). In video the trunk runs once per frame and the propagation set feeds the tracker; the interactive set is computed only when masks are fed in as conditioning (`comfy/ldm/sam3/tracker.py:1566-1568`).

Meta: `meta_sam3/sam3/model_builder.py:383-397` and `meta_sam3/sam3/model/vl_combiner.py:196-273`.

Verdict: same structure (read). Not run against Meta.

### 4.7 The detector

In: the last detector map flattened to [B, 5184, 256] with positions; text features [B, 32, 256] with a mask. With no points or boxes, an empty geometry prompt and one extra class token are appended: [B, 33, 256] (`comfy/ldm/sam3/detector.py:440-458`).

Steps (`comfy/ldm/sam3/detector.py`):
- Encoder, 6 layers: image tokens attend to each other and to the text. Output [B, 5184, 256] (`:107-120`).
- Decoder, 6 layers: 200 learned queries and one presence token attend among themselves, to the text, and to the image with a position bias from each query's current box. Boxes start from learned reference boxes and are refined at every layer (`:145-215`). Output: query features [B, 200, 256], boxes [B, 200, 4] (centre and size, 0 to 1), presence logit [B, 1].
- Scores: the text features pass a small network and are averaged over real tokens; each query is projected and dotted with the average, divided by 16 and clamped to plus or minus 12: [B, 200] (`:367-385`).
- Masks: two upsampling steps (72 to 144 to 288 wide) build a [B, 256, 288, 288] map from the three feature maps, and each query's mask is the dot product of its mask embedding with it: [B, 200, 288, 288] logits (`:338-364`).

The detect node scales boxes to the frame and resizes all 200 masks to the frame size before keeping any (`:483-486`). The video path runs the same stages on the cached trunk output and leaves masks at 288 by 288 (`:495-509`).

Meta: `meta_sam3/sam3/model_builder.py:87-250` and `meta_sam3/sam3/model/model_misc.py:741-800`. Meta multiplies each query's class probability by the presence probability before thresholding (`meta_sam3/sam3/model/sam3_image.py:348-356`).

Verdict: same (run) on what the detector is confident about: with Meta's own loaded image tensor given to both, the presence logit agrees, both keep the same two detections, and their masks agree (section 7). Among low-scoring queries the scores and masks wander, which is read as float32 against bfloat16. One frame and one phrase; the structure and constants were also read. Different, a departure (read): ComfyUI computes the presence logit and never uses it.

### 4.8 The detect node's own steps

In: boxes, scores and masks for every query. Out: a MASK [B, H, W] (or [N, H, W] with `individual_masks`) and a list of boxes with scores.

Where: `comfy_extras/nodes_sam3.py:208-255`. Keep queries whose class probability is above `threshold` (default 0.5, `:105`), sort by score and keep the first `max_det` (the phrase's count; 1 if none, `:32-38`); no overlap removal. For each kept detection, `_refine_mask` (`:42-87`) crops the frame around the box with 10 percent padding, resizes the crop to 1008, runs the interactive SAM decoder `refine_iterations` times (2 by default, `:106`), pastes the result back and takes the union with the detector's own mask. Unless `individual_masks` is on, all detections of a frame merge into one mask.

Meta: nothing like this on the detection path; the detector's mask is used directly (`meta_sam3/sam3/model/sam3_multiplex_base.py:1611-1626, 2766-2774`), with a joint score and a different threshold and overlap rule (`meta_sam3/sam3/model_builder.py:631-646`).

Verdict: different. The score the node thresholds (the class score alone, where Meta thresholds class times presence) and the absence of overlap removal among detections are departures, found independently of the notes this page rests on (section 7); the threshold values are choices. The refinement is also a departure, because every mask this node returns has passed two extra decoder runs and a union.

### 4.9 Seeding the tracker

In: for seed masks, `initial_mask` [N_obj, H, W], float, one mask per object at the frame size, used on the first frame of the batch only (`comfy/ldm/sam3/tracker.py:1703`). For a text start, the first frame whose detections pass the threshold supplies the masks (`:1713-1727`).

Steps:
- Each mask is resized to 1008 by 1008 bilinearly and set to 1 above 0.5 (`:1562-1564`), and the frame's interactive feature maps are computed (`:1566-1568`).
- The mask becomes the first stored result with no decoding: logits `mask * 20 - 10` and an object score fixed at +10 for a non-empty mask (`comfy/ldm/sam3/tracker.py:332-347`). The object pointer, a 256-number summary of the object that later frames read, comes from the interactive decoder given the mask as a prompt, using its first output token.
- The first memory is encoded from it, flagged as a clean mask (`:1313-1349`): mask values are squashed to 0 to 1, rescaled to -1 to 1, resized to 1152 by 1152 (`:598`), packed with 16 slot masks and 16 flags per bucket, and reduced by a convolution stack to the 72 by 72 grid (`:1177`), giving [buckets, 256, 72, 72].
- This result is stored as a conditioning frame, which is never deleted.

Meta: `meta_sam3/sam3/model/video_tracking_multiplex_demo.py:1667-1850` (`add_new_masks`) follows the same path and resizes the seed to 1152 instead of 1008.

Verdict: same structure and constants (read); the 1008 against 1152 resize is a choice. Not run against Meta.

### 4.10 One tracked frame

In: the frame's propagation maps [1, 5184, 256], and the memory per bucket: the last six frames' memory maps, the conditioning frame(s), and the object pointers of up to fifteen earlier frames and of the conditioning frames (`comfy/ldm/sam3/tracker.py:221-256, 1237-1254`; the counts come from `:1152, 1160`).

Steps:
- Memory attention (`:1217-1311`): four layers, eight heads, width 256 (`:1165`). The frame's tokens attend to the memory, with image features and memory features in separate streams. Output [buckets, 256, 72, 72].
- The multiplex mask decoder (`:767-860`, called at `:1365`) decodes all 16 slots of a bucket at once. Per slot it returns three candidate masks (`:1169`), a quality estimate for each, a pointer token and an object-score logit; masks are [buckets, 16, 3, 288, 288], regrouped per object.
- Per object the candidate with the best quality estimate is kept. If the object score is 0 or below, the mask is replaced by a constant very negative value and the pointer by a "no object" pointer (`:1380-1395`). The mask is upsampled to 1008 by 1008 in float32.
- The pointer is built from the first output token, not from the token of the chosen mask (`:1391`).

Meta: memory attention is `meta_sam3/sam3/model/decoder.py:1151-1437`; the pointer comes from the token of the best-quality mask (`meta_sam3/sam3/model/multiplex_mask_decoder.py:209-215`).

Verdict: same layout and the same object-score gate (read). By outcome (run), alike on small groups given the same seeds: the largest person alone is lost within a few frames in ComfyUI with and without the range mapping and in Meta's tracker, the first sixteen of a seeded set hold to the end in all three, and for the largest person with one neighbour ComfyUI with the range mapped and Meta's tracker agree. For the seventeenth person the two end at frames 6 and 6 on one set of seeds and 17 and 8 on another. Beyond sixteen seeded people the arms are not comparable from single runs: a change of about two levels of 255 in the input moved one arm by twelve people (section 7). Meta's tracker-only path applies neither of the between-object rules of 4.11 and ComfyUI applies both with its own values; whether any difference comes from those rules or from the port was not separated. The pointer token is different, a departure; it is real in the code and was measured not to be the cause of the losses (section 7).

### 4.11 After each tracked frame

These steps change the stored low-resolution (288 by 288) mask, which is what later frames remember. They do not change the high-resolution mask returned for the current frame.

- Small foreground pieces and small holes in the stored mask are removed or filled, up to 16 pixels; a foreground piece goes only if it is also no more than half the mask (`comfy/ldm/sam3/tracker.py:116-136, 1747-1748`).
- When two masks overlap by 0.3 or more (the larger of intersection over union and intersection over the smaller mask), the one occluded more recently is set to -10 (`:1486-1507`).
- For the memory only, an object whose mask shrinks to under 0.3 of its size once overlaps are resolved is treated as absent (`:1514-1524`).
- The frame's memory is encoded from the stored mask (`:1509-1539`), the frame is stored, and stored frames older than 16 are deleted, except conditioning frames (`:1754-1758`).

The matching step in 4.12 reads the same stored masks, so a suppressed mask can fail to match its own detection (read, not run).

Meta, 3.1 builder: suppression at 0.7 that also changes the returned masks, and a hole fill of 0 (`meta_sam3/sam3/model_builder.py:640-654`). The value 16 is the original SAM 3 builder's (`coderef/sam3/sam3/model_builder.py:759`).

Verdict: different. The thresholds are choices; that these edits do not reach the returned mask is a departure. The memory-shrink rule is the same (read).

### 4.12 Looking for people while tracking

This runs on video with a conditioning (`comfy/ldm/sam3/tracker.py:1688-1701, 1760-1767`; `_match_and_add_detections` at `:1578-1643`) and never on a seed-only run.

- Every `detect_interval` frames the detector runs on the cached trunk output. Detections above `detection_threshold` go through overlap removal at 0.5 (`:72-94`).
- A track is matched if any detection overlaps it by 0.5 or more (`:1599`). A detection that overlaps no track by 0.5 becomes a new object while fewer than `max_objects` are tracked (`:1629-1636`), and enters memory as a clean mask.
- A detection scoring 0.8 or more that overlaps a track by 0.5 or more replaces the tracked mask on that frame, and the memory is re-encoded (`:1607-1626`).
- A per-track counter goes up by one when matched (to 8) and down by one when not (to -4); a track at 0 or below is blanked in the output. Seeds start at 8, new objects at 1 (`:1584-1605, 1639-1641, 1710-1712`).

Meta, 3.1 builder values (`meta_sam3/sam3/model_builder.py:631-646`): a detection is kept above a joint score of 0.4, and overlapping detections are removed at 0.1 on the intersection over the smaller mask. A new object needs a score of at least 0.65 and no track overlapping it by 0.1 or more on that same smaller-mask measure (`meta_sam3/sam3/model/sam3_video_base.py:166-265`), so a mask lying inside an existing object is not new. New objects must be confirmed on 3 consecutive detections (`meta_sam3/sam3/model/sam3_multiplex_base.py:250`). A hotstart rule holds objects for 15 frames and removes ones that stay unmatched or duplicate another for 8. Detections close to the frame edge are suppressed. Every 16th frame a detection scoring 0.8 or more can refresh a track, but only if it overlaps exactly one track by 0.5 or more on the smaller-mask measure (ambiguous matches are dropped, `meta_sam3/sam3/model/sam3_video_base.py:224-245`) and the tracker's own object score is above 0.8 (`meta_sam3/sam3/model/sam3_multiplex_base.py:867`).

Verdict: different, a departure: ComfyUI's loop is a reduced version of Meta's session logic, with other measures and thresholds.

### 4.13 Output

Out of `SAM3_VideoTrack`: a `track_data` dictionary. Its main entry is the packed masks, uint8 [frames, objects, 1008, 126], one bit per pixel, made by thresholding the 1008 by 1008 masks above 0 (`comfy/ldm/sam3/tracker.py:194-198, 1769-1776`); it also holds the frame count, the original frame size and one creation score per object. It sits on the intermediate device.

Out of `SAM3_TrackToMask`: a MASK [frames, H, W], float32. It takes a comma list of object indices (empty means all), combines the chosen packed masks with OR, unpacks them and resizes bilinearly to the frame size (`comfy_extras/nodes_sam3.py:493-518`), so edges are soft: values between 0 and 1. `SAM3_TrackPreview` writes a coloured overlay with object numbers to a temporary video (`:315-470`).

Meta: logits are resized to the frame size as floats and thresholded once, and the masks of different objects are made exclusive (`meta_sam3/sam3/model/video_tracking_multiplex_demo.py:1908-1930`).

Verdict: different, a departure: ComfyUI thresholds at 1008 and then resizes a 0/1 mask, so there is a second resample and soft edges, and objects can overlap.

## 5. Memory: what is on the card and who counts it

- The model. ComfyUI's model manager counts the weights. Each SAM node calls `load_model_gpu(model)` (`comfy_extras/nodes_sam3.py:152, 288`), which loads with a memory request of zero and so reserves only the minimum inference memory (`comfy/model_management.py:890-891, 939-947, 1041-1042`). The weights are the file's values cast to the compute type, float16 here.
- Nothing else is counted. A search of `comfy/ldm/sam3/` and `comfy_extras/nodes_sam3.py` finds no call to the memory manager for the tracker's state, features or outputs, so ComfyUI does not limit them.
- The tracker's per-frame entries (`comfy/ldm/sam3/tracker.py:1754`): memory maps, frame features and positions, stored low-resolution masks, pointers, and the high-resolution mask [objects, 1, 1008, 1008] in float32, about 4.1 MB per object per frame. That last one dominates. The loop keeps the current frame and the 16 before it (`:1755-1758`), so at the 64-object ceiling (`:1645`) it is about 4.4 GB (64 objects x 17 frames x 4.1 MB, by arithmetic) plus the maps. The conditioning entry is never deleted. The next frame's features are computed on a second CUDA stream while the current frame is processed (`:1667-1686`), so two frames of features are alive at once.
- The packed output masks: 127 KB per object per frame (1008 x 126 bytes), on the intermediate device, which is system memory unless `--gpu-only`. At 64 objects and 345 frames that is about 2.8 GB, and the final stack pads every frame to the largest object count, which copies it once more (`:1790-1802`).
- The input frames stay as float32 on the intermediate device; one frame at a time goes to the GPU.
- The detect node holds a [1, 200, H, W] mask tensor in the model type before keeping any: about 408 MB at 1344 by 760 in float16 (arithmetic, `comfy/ldm/sam3/detector.py:483-486`).
- Measured, for 72 frames in float16: about 0.9 GiB over the model for one or two objects, about 6.3 GiB for about sixty (section 7).

## 6. What a user of the stock nodes should know

- Counts: `person:16` keeps up to 16 detections of "person" in `SAM3_Detect` (`comfy/text_encoders/sam3_clip.py:30-47`); a phrase with no count keeps one (`comfy_extras/nodes_sam3.py:32-38`); commas separate phrases. The trap is `person:1`: it is the one case the count syntax skips, so the text `person:1` itself reaches the text tower and changes the result (`comfy/text_encoders/sam3_clip.py:51-54`). Use a count of 2 or more, or no suffix. The video node drops the counts (`comfy_extras/nodes_sam3.py:303`); `max_objects` is the limit there.
- Tokens: the text tower reads 32 tokens including start and end (`comfy/text_encoders/sam3_clip.py:21, 26`), so at most 30 tokens of phrase.
- The stock video-segmentation template runs `SAM3_Detect` on every frame and has no tracker. The stock templates that do track (the character-replacement templates and the body-model template) start the tracker from text with `max_objects` 4, `detect_interval` 1 and threshold 0.5 (`coderef/workflow_templates/templates/video_wan21_scail2_character_replacement.json` and `utility_sam3d_body.json`, widget values of `SAM3_VideoTrack`).
- `max_objects` defaults to 4 and ranges from 0 to 64 with 0 meaning 64 (`comfy_extras/nodes_sam3.py:276`); the code ceiling is 64 (`comfy/ldm/sam3/tracker.py:1645-1652`). Seed masks are not limited by it: all given seeds are tracked, and it only limits objects added by detection.
- Seeds are used on the first frame of the batch only. To seed later, cut the frames so the batch starts there.
- The end of `SAM3_TrackToMask` is a soft mask; threshold it if a binary mask is needed.
- Frames reach the trunk in 0 to 1 where the model was built for -1 to 1 (section 4.4). Mapping the frames to -1 to 1 before the nodes (`frames * 2 - 1`) needs no change to ComfyUI's files; its effect depends on the frames (section 7). Mapping the range and switching the text activation correct those two departures and nothing else: the resize (4.4), the detection rule and the refinement (4.8), hole fill and the between-object rules (4.11), the pointer token (4.10) and the output order (4.13) stay ComfyUI's.
- `SAM3_Detect` refines every mask twice by default (`refine_iterations`, `comfy_extras/nodes_sam3.py:106`); 0 returns the detector's own masks. The presence output is computed and ignored.

## 8. Not established

- The floor of the float32-against-bfloat16 comparisons (text, trunk, detector): ComfyUI's own network at float32 against itself at bfloat16 on the same tensor is the control, and it was not run.
- The detector against Meta beyond one frame and one phrase: the outputs agree on confident queries and are unstable among low-scoring ones; other phrases and frames, and the intermediate tensors of the encoder, decoder, mask head and geometry encoder, were not compared.
- The tracker against Meta step by step: the conditioning output, pointer, memory-attention output, memory maps and object scores were not compared. The whole-track outcomes were compared once (section 7).
- Any difference between ComfyUI and Meta's tracker beyond sixteen seeded people. There is one run per arm, and a change of about two levels of 255 in the input moved one arm by twelve people. On the loader node's frames ComfyUI kept 16 to 20 of 32 in four runs and Meta's tracker kept 31 and 32 in two; ComfyUI kept 32 once on the other decode (numbers in section 7). That ComfyUI is less tolerant than Meta's tracker, and whether the between-object rules or the port are behind any difference, is not established.
- That a neighbour cures a lone person's collapse: it did on one set of seeds (the pair held to the end with the range mapped and in Meta's tracker) and did not on the other (the pair ended at frame 8 in all three arms). That the source of the seeds explains any of this is not established.
- Each arm repeated under a small change of input, in both codebases: not run. Meta's full session logic (4.12) was not run either; the comparison used its tracker-only propagation. Which lone people collapse: the largest person alone was lost within 2 to 5 frames in every run, in both codebases; the seventeenth alone ended anywhere from frame 5 to frame 17 depending on the arm and the seeds (section 7); no rule for which lone person is lost has been found.
- Which of the frame-rate change, the resize or the choice of seeded people accounts for the losses on the lane's frames. A benefit of the mapping for tracking shows in some arms and is inside the noise in others; none of the three was separated.
- The text features at padding positions differ between the two towers whatever the activation (seen in a scratch probe, `rung2_text.py`, not tracked). Both give the detector a mask over them, so it is expected to be inert; that was not shown.
- How the detect node treats a phrase longer than 30 tokens that ComfyUI splits into a second row.
- The effect of hole fill, suppression and the memory-shrink rule on tracks, and of the 1008 resample on mask edges: read, not measured.
- Non-ASCII text against upstream: the copy runs without `ftfy`, so tokens are equal to the copy, not to upstream.
- The pack's float32 repack against Meta's original `.pt`, tensor by tensor.
- Compute precision beyond what its record covers: one test clip, three stretches, sixteen people, one card. More than sixteen people and Meta's own predictor as an arm were not run (section 7).
- The edits in `meta_sam3/EDITS.diff` to `meta_sam3/sam3/model/decoder.py`, `meta_sam3/sam3/model/memory.py`, `meta_sam3/sam3/model/position_encoding.py`, `meta_sam3/sam3/model/sam3_tracker_base.py` and `meta_sam3/sam3/model/video_tracking_multiplex.py` were not read, so a "same" resting on one of those files is "same as the copy".
