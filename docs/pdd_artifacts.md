# PDD artifacts: the master inventory

Every Parallel Decoding Distillation (PDD) weight file on this box: what it
is, when it was made, by which converter version and commit, what changed
between versions, and which file to load on which checkpoint. Read this before
touching a PDD file or wiring one into a graph.

**Two kinds of content live here, and they are kept apart on purpose.** The
inventory table between the two marker lines is GENERATED by
`bench/pdd_artifact_inventory.py` from each file's own metadata and from
`workflows/h3_config.py`; never hand-edit it, and run the script with `--check`
before trusting it. Everything outside the markers is written by hand: the
glossary, the decision table, and the two changelogs. Those are decisions and
history, which no file records about itself. [`h3_pdd.md`](h3_pdd.md) is the
long-form owner of the mechanisms and the measurements; this page only says
which file is which.

## 1. Glossary, including the word "baked", which means two different things

**The source.** alibaba-pai publishes one PDD LoRA per partition,
`MiniMax-H3-{FL2VA,Ref2VA}-Acc-8Step.safetensors`, in diffusers naming. Each
holds three mechanisms: 312 LoRA modules over the 50 transformer blocks and the
2 token-refiner blocks (the backbone), 50 LoRA modules on `adaln_proj.linear`
(the modulation update), and `proj_out` / `audio_proj_out` replaced by a stack
of 32 per-interval output heads. PDD is not a step distillation: the heads are
what makes parallel decoding possible, and the backbone and adaln updates are
what the distillation taught the model to feed them.

**Our conversion** (`bench/convert_pdd_lora.py`) turns one source into one
file `MiniMaxH3PDDLoRA` can load, on three surfaces:

- the **backbone**, renamed to ComfyUI's generic LoRA keys
  (`diffusion_model.blocks.N.{attn.qkv_proj, attn.out_proj, mlp.fc1, mlp.fc2}`
  after the q/k/v fuse and the SwiGLU half swap, plus
  `diffusion_model.token_refiner.blocks.N.*`): 208 modules, applied by
  ComfyUI's own weight-patch path;
- the **adaln update**, in one of two forms (next paragraph);
- the **head bank**, `h3_pdd.bank.*`: the published 32 heads verbatim, fused
  at load time for whatever step count the sampler runs.

**The two adaln forms are the only difference between the two conversions of
one source.** An H3 checkpoint is either *pruned* (its adaln time embedder is
replaced by an 8-column curve table; `adaln_proj.linear.weight` is
`[96768, 8]` and `adaln_t_table` is present) or *unpruned* (`[96768, 2688]`,
no table). Every checkpoint this repo ships graphs for is pruned.

- `..._pdd_8step_comfy.safetensors`: the adaln update **pre-solved into the
  pruned checkpoint's rank-8 curve basis**, stored as `h3_pdd.adaln_baked.*`
  `diff` / `diff_b` tensors, applied as ordinary weight patches. Fits the
  pruned build whose table it was solved against and nothing else. This is
  the default and what every shipped PDD graph wires.
- `..._pdd_8step_adaln2688_comfy.safetensors`: the adaln update as the
  original **2688-dim LoRA pairs** (`h3_pdd.adaln.*`) plus the time grid the
  runtime injection needs (`h3_pdd.silu_temb_grid`). Loads on either build:
  a weight patch on an unpruned base, 50 runtime forward patches on a pruned
  one.

Both carry the same backbone and the same bank, bit for bit.

**"Baked" has two meanings here, and a sentence that does not say which is
ambiguous.**

1. **adaln bake**: the paragraph above. The adaln *update* solved into the
   checkpoint's curve basis and stored in the sidecar. This exists today; every
   `_comfy` file has it (`h3_pdd_adaln_form: baked`).
2. **backbone bake**: folding the 200 backbone LoRA modules into the int8
   checkpoint's weights *offline*, producing a **baked checkpoint** plus a
   **stripped sidecar** (the same file with its `diffusion_model.blocks.*`
   tensors removed). This is the lever `h3_pdd.md` argues for, because merging
   at load requantises the weights with stochastic rounding and a bake does
   not. **It does not exist yet**: no baked checkpoint and no stripped sidecar
   is on disk, and the bake script is unwritten.

**Full and stripped.** A *full* sidecar carries the whole backbone (every
file on disk today). A *stripped* one carries none of it and is paired with
exactly one baked checkpoint; the converter cuts it with
`--omit-backbone --baked <that checkpoint>`.

**The probe.** Since converter version 3 every file stores 64 rows of
`blocks.49.mlp.fc2.weight`'s int8 codes and fp32 row scales, cut from the
checkpoint the file is paired with (`h3_pdd_backbone_probe_of`: `base` for a
full file, `baked` for a stripped one). The node requires the loaded module to
equal them before patching. That is how a full sidecar refuses a baked
checkpoint (the backbone would go on twice) and a stripped sidecar refuses
everything but its own bake.

**Kijai's conversions** (`MiniMax-H3-*-Acc-8Step_comfy.safetensors` and
`_pruned_comfy`) are a different format from a different author: no metadata,
the bank fused at run time, 528 or 578 tensors. They are here as an
independent control for `bench/compare_pdd_conversions.py` and are never wired
into a graph.

## 2. Which file to load, on which checkpoint, and what happens if you do not

| the checkpoint you are loading | load this | why |
|---|---|---|
| a **pruned** int8_convrot build (`minimax_h3_{fl2va,ref2va}_pruned_int8_convrot`), which is every shipped graph | `..._pdd_8step_comfy` of the same partition | adaln applied as weight patches; cheapest path |
| an **unpruned** int8_convrot build (`minimax_h3_{fl2va,ref2va}_int8_convrot`) | `..._pdd_8step_adaln2688_comfy` of the same partition | the only form whose adaln fits a 2688-wide time space |
| a **baked** checkpoint (none exists yet) | the stripped sidecar cut against that exact file | anything else applies the backbone twice or not at all |

The node decides by observables on the loaded model (`use_adaln_curves`, the
live adaln table, the output head, the probe) and never by filename. Wrong
pairings, and what the node does:

| pairing | outcome |
|---|---|
| `_comfy` (adaln baked) on an unpruned base | **refused**: none of its 50 adaln modules can be applied, and the message names the `_adaln2688` file. Before 2026-08-31 this rendered with no modulation update and looked normal |
| `_adaln2688` on a pruned base | **works**, through 50 runtime forward patches instead of weight patches: slower per step, same result to within the adaln bake's residual, which is far below the pruning error the checkpoint already carries |
| fl2va file on a ref2va base, or the reverse | **refused** by the partition check on `final_layer.video_out`; the two partitions ship identical key sets, so nothing else would notice |
| a `_comfy` file whose adaln was solved against another table | **refused** by the table guard |
| full sidecar on a checkpoint that is not its base (a bake) | **refused** since converter version 3, by the probe: the backbone would be applied a second time |
| stripped sidecar on the base, or on any bake but its own | **refused** since version 3, by the probe; the message says which |
| `strength` other than the bake's, or `unmerged_blocks`, with a stripped file | **refused** |

## 4. Converter changelog

The version string in the file (`h3_pdd_converter_version`) is what the node
reads. **No version ever changed the weights**: every regeneration was
verified tensor by tensor against the file it replaced, and the only
differences between versions are sidecar tensors and metadata. Commits are in
this repo's history.

**Version 1, 2026-08-26 to 2026-08-31.** The version string did not move
during these changes, so a version-1 file's contents depend on its date.

- 2026-08-26 (`7f460f7`, `ddc2ac9`, `e917a35`, `548629e`, `c839e22`): the
  converter, the shared schedule math and the node. The adaln update baked into
  the pruned checkpoint's curve basis (`--pruned`) the same day, and one adaln
  form per file rather than both.
- 2026-08-27 (`d28b7a6`, `142bfc9`): the precomputed fused heads
  (`h3_pdd.head.*`) RETIRED for the raw 32-head bank (`h3_pdd.bank.*`), fused
  at load for any step count, so one file serves 8, 4, 2 or 16 evaluations.
  Also fixed: `--pruned` runs exited non-zero after writing a correct file.
- 2026-08-28 (`ca0c245`): the bank asserted verbatim at conversion, refusing a
  delta-encoded re-upload of the source.
- 2026-08-29 (`6fab6b0`): explicit `alpha` tensors for the adaln pairs, since
  ComfyUI reads alpha from a tensor and never from metadata. Files converted
  before this carry none (PDD's alpha/rank is 1.0, so the fallback happened to
  be right).
- 2026-08-31 (`5f9ae6f`): metadata `h3_pdd_adaln_form`, `h3_pdd_loads_on`,
  `h3_pdd_pruned_base`, because `h3_pdd_base` records the `--base` argument,
  which for a `--pruned` conversion is the one checkpoint the file refuses. The
  shipped files were not regenerated for this; the node classifies version-1
  files by key prefix, which needs no metadata.

**Version 2, 2026-09-02 (`2404409`).** Superseded the next day. Added the
backbone probe (int8 codes only, always cut from the base), `--omit-backbone`
for stripped sidecars, `h3_pdd_backbone` and `h3_pdd_backbone_strength_baked`,
`backbone_modules` counting what the file carries and
`backbone_modules_converted` the modules converted; stopped leaving 50 inert
adaln `alpha` tensors behind on the `--pruned` path. Codex's audit found that
a stripped file's check proved "not the base" rather than "this exact bake",
that a scale-only change escaped, and that the population was derived from
the input. **The node refuses version-2 stripped files** as incomplete;
version-2 full files were regenerated at version 3 the same day.

**Version 3, 2026-09-03 (`e38655d`, then `eb791f8`).** The probe carries the
fp32 row scales as well as the codes and is cut from the ONE paired
checkpoint (`h3_pdd_backbone_probe_of`); the node requires exact equality on
both. `--omit-backbone` requires `--baked <checkpoint>` and refuses a bake
identical to the base; a stripped file also carries the base's slices so the
refusal can say "this is the unbaked base". The population is asserted
against the release's declared depth (`vendor_config.transformer_depth()`,
from the two `transformer/config.json` files vendored that day) rather than
counted off the input. `eb791f8` added `h3_pdd_converted_on` and
`h3_pdd_converter_commit`.
