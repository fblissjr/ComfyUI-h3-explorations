MiniMax H3 · Sol-Attn · 2026-09-01

Sol Routing, Observed

Where the day started, what the live route records showed and did not show, which claims changed under them and why, and what that buys next.

Where we started

Every routed-density number this repo had ever quoted for Sol-Attn was an offline approximation. bench/analyze_routing.py re-derives the router's decision from the eager reference on captured activations, in float arithmetic the kernel does not use, on the few blocks and steps a capture happened to hold. The kernel computes the real thing on every call: its route stage writes one integer per (batch, head, query block) that the exact stage then walks. The public API discarded that integer along with the workspace. Codex's joint plan for the morning made recovering it the one bounded milestone for this lane, with a strict rule: read it from the same launch that produced the attention output, never rerun routing to look at it, and leave the normal path doing no observation work.

That does not make the earlier numbers worthless, and it is worth being exact about what changed. An offline approximation re-derives the router's rule in float arithmetic from captured activations; the kernel routes from int8 proxies. On a synthetic fixture today the two disagreed on about a tenth of a block per query block, with 89.5 percent of rows identical, so the old method was close. Its limits were elsewhere: it covered the blocks and steps a capture happened to hold, at whatever tau and geometry that capture used. Codex's 2026-08-31 sweep, at tau 1.0 on the captured PDD cells, estimated kernel density between 20 and 22.5 percent; the live records read 23.1 percent on the PDD graph and 23.4 on the base graph, every block and every in-window step. The approximation held to within a couple of points. What changes is which number is citable, at which settings, and that the live one costs a render rather than a capture.

The protocol was one audit checkpoint, one adjudication, one implementation, one handoff. What actually happened was that plus two review rounds, three canonical renders at 1344x768 and 345 frames, and a mid-afternoon in which Codex went offline and the owner directed the rest.

What got built

On the comfy-kitchen side, a branch two commits past upstream c1c6751 adds one optional out-parameter to sol_attn. When a caller hands it an int32 buffer of shape (batch, heads, query blocks), the CUDA backend copies the plan's count slot into it on the same stream after the launch. Eager fills the same buffer from its own route mask, HIP refuses it until someone with an AMD card verifies the slice, and None allocates, copies and synchronizes nothing. The wheel every record below was captured on is 0.2.31+sol.24908e1; the evening's second variant, 0.2.31+sol.d25f2e8, replaced it afterwards (the section on the two variants says what differs). Both the version string and the local segment are recorded because a requirements reinstall replaces either silently.

On this pack's side, sol_observe.py writes one JSON line per attention override call when the server was started with H3_SOL_OBSERVE in its environment, plus a uint16 sidecar holding the full count tensor. Each row carries call-time identity (the prompt id ComfyUI's history uses, read from the executing context), the transformer block, the sigma with a justified schedule index, the selection and sinks, the route actually taken, and for Sol calls the density figures. A render row per prompt names the workflow file by graph hash and says whether the process was cold or warm. The producer asserts its own shape and aborts the render rather than thinning the file.

Four things the records settled

  • The windows do what the arithmetic said. The base graph ran Sol on 11 of 16 forwards and the PDD graph on 4 of 8, the figures pdd_math.py had computed and the profiler scaffold had carried since August. They were never observed until today.
  • Routing is a function of the inputs, not of the cache. The owner asked whether ComfyUI's caching or dynamic VRAM could reach the numbers. The PDD graph rendered cold, first prompt after a restart, and again warm in a different process after a 16-step render, produced bitwise identical counts on all 184 paired Sol calls. Densities from one record are the graph's, not one process's.
  • Text rows route less than video rows. On the PDD graph's first in-window forward the text segment's ordering-effect density was 0.165 against 0.209 for video. That is a query-segment figure with overlap weights; whether it means anything for output is not something a count can say.
  • Density barely moves across the window. Per-forward means run from 0.2093 to 0.2074 across the PDD graph's four in-window forwards, and from 0.2119 to 0.2079 across the base graph's eleven. At tau 1.0 the router is doing nearly the same amount of work at every sigma it is active on.

The live render is the observable. Where a claim could be checked against a closed-form prediction on the whole tensor, it held; where it rested on a code path nobody had executed, it did not.

What we did not learn

  • What the routing costs in output. A count says how much of the key sequence a query block walked exactly, not what the pooled tail left out. No reference output was involved. Density is the cost side of the trade, and nothing here ranks quality.
  • Which key blocks were chosen. The kernel's routed list is not recorded, only its length per query block. Key-segment questions need blk_idx, which is a separate decision about disk.
  • Anything about time. Every armed render synchronizes the stream once per Sol call to copy its counts; the record's header says timings are not quotable and they were not quoted. Stage-level profiling remains scaffolding.
  • Blocks 0, 1, 2 and 32. They are dense in the shipped configuration, so the record cannot say whether block 0 still routes about 1.7 times the deeper blocks, as the 2026-08-16 offline table measured at tau 1.3 on four heads of a reference-heavy capture. That table stands as what it was; it is not the number to quote for the shipped configuration, and one armed render with the dense list empty would replace it.
  • A second scene or seed. One prompt, one seed. Every figure above is a single sample of a distribution nobody has measured yet.

So what

Until this morning, any decision about tau, the sigma window, the dense-block list, or which backend takes a fallback had to be argued from captures that covered three blocks and two steps. Now a canonical render leaves a few hundred kilobytes that answer, per block and per step, what the router actually did, and a comparison tool says whether two renders routed the same. That turns the next round of Sol arms from anecdote into measurement: a tau of 0.85 can be characterised by its density profile before anyone spends a blinded screen on it, and the merged-against-baked PDD comparison can record both arms' routing before attributing a difference to the bake.

The controls that make the numbers trustworthy are cheap and already run: exact closed-form counts at both tau extremes, elementwise monotonicity in tau, bitwise-unchanged output with the buffer present, refusal of a wrong buffer, and a structural grader on every live record. The positive and negative pair Codex owed on the CUDA wheel ran through the public API on a hand-written five-block fixture and holds: [2, 3, 4, 5, 4] / [2, 3, 4, 5, 4].

The chunked producer, built and measured

The page above said our node "cannot reach" comfy-kitchen's chunked producer. That was true of the seam and false of the repo, as the owner pointed out, so it was built the same evening: MiniMaxH3SolChunked publishes the delegate Sol's composition gate already prefers, runs the QKV projection over 64-aligned chunks, and feeds them to sol_attn_chunked, which applies the same fused norm-and-rope core applies. At toy scale it does what upstream says: cosine 0.99995 against the direct path, and 87 MiB of peak allocation over a 32k-token call against 192.

At canonical geometry it does not deliver the lever, and the record says why. On the shipped PDD graph the shipped arm's peak was already 11.68 GiB at the end of its first forward, which runs on Sage outside the Sol window, and 11.88 GiB by the end; the direct Sol call never set the peak. The chunked arm's first in-window call raised it to 12.87 GiB. The Q, K and V the producer avoids are not where this graph's peak lives, and the producer's own working set costs about a gigabyte more. It also routes a different block set at the same density: 0.2090 against 0.2090 at the first in-window forward, agreeing on 23 percent of head and query-block pairs there and 11 percent by the fourth, as its previous-step key statistics drift from the direct path's current ones. What that costs in output is unmeasured, and a count cannot say.

So the node stays an experiment, not a default, and the finding that outlives it is about where the peak sits: outside attention. Lowering peak memory on this graph means looking at the dense forward and the MLP, not at Sol's tensors. The record that established that cost two renders and a field that reads the allocator for free.

Sources: bench/results/2026-09-01_sol_route_pdd8_direct_ab.json, ..._pdd8_chunked_ab.json, ..._pdd8_direct_vs_chunked.json; the node's own check is bench/check_sol_chunked.py. The peak field was cumulative across prompts in this run and is reset per prompt since; the ordering of the two arms is what makes the attribution.

Going forward

  • Uninstrumented renders for anything timed; the armed record is for routing only.
  • A second scene and seed before any density figure informs a default.
  • One armed render with the dense-block list empty, as an experiment arm, to settle whether block 0 is still the outlier at tau 1.0 over all 56 heads.
  • Render both bake arms armed and compare their routing call for call before reading the merged-against-baked result.
  • Use the route record to choose which cells the Tier 1 activation capture holds, instead of guessing.
  • The upstream pull request is the owner's call; the branch is on the fork. Rebase first if PR 146 or the continued branch moves the plan's count slot.
  • Where the peak sits on the canonical graph: instrument the dense forward and the MLP the way attention is now instrumented, since that is where a memory lever would have to act.
  • Housekeeping the day exposed: a test that drives the chain probe under an executing context, a workflow-aware --steps in the smoke harness, submodule and path checks in the rebuild script, and the restart script's hang at exit when its output is piped. Its caller-killing pkill is already fixed.
