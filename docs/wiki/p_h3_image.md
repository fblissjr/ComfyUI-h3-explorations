## 1. How PrunaAI Built `P-H3-Image` from `MiniMax-H3-26B`

`P-H3-Image` adapts the 26B `MiniMax-H3` (`fl2va`) audio-video diffusion transformer for **single-frame (`t=1`), audio-free** image generation (`~8.48 MP`, `2912x2912` default) and multi-reference image editing (`1..8` reference images). Across the checkpoint files and `diffusers` `src/diffusers/modular_pipelines/p_h3_image/`, five components differ from stock MiniMax-H3:

| Component | Stock MiniMax-H3 Video (`fl2va` / `ref2va`) | PrunaAI `P-H3-Image` (`workflows/image/`) | ComfyUI Core & Pack Code |
|---|---|---|---|
| **DiT Backbone & LoRA** | `minimax_h3_fl2va_pruned_int8_convrot.safetensors` (`20–50` steps or 6-step Pika `lcm`) | `p-h3-image_int8_convrot.safetensors` (`24 GB` merged int8 ConvRot) **or** `h3/p-h3-image_lora_bf16.safetensors` (`3.5 GB`, `rank=128` across all 50 DiT blocks + `token_refiner`) applied onto `unet_fl2va` via [`MiniMaxH3LoRABranch`](../../lora_branch.py) | `comfy/ldm/minimax/model.py`; [`lora_branch.py`](../../lora_branch.py) |
| **Step & Sigma Schedule** | `MiniMaxH3SigmaShift(shift_video=12.0, shift_audio=3.0)` + `BasicScheduler("simple")` | `MiniMaxH3SigmaShift(shift_video=1.0, shift_audio=1.0)` + `ManualSigmas` set to the non-uniform 8-step distillation grid `1.0, 0.984753, 0.967905, 0.951688, 0.925372, 0.881923, 0.810083, 0.528718, 0.0` (`PH3_IMAGE_MANUAL_SIGMAS`), `KSamplerSelect("euler")`, `BasicGuider` (`cfg=1.0`). 6 of the 8 steps sit in `[1.0 -> 0.81]` | [`workflows/h3_config.py`](../../workflows/h3_config.py) (`PH3_IMAGE_MANUAL_SIGMAS`, `PH3_IMAGE_SHIFT`) |
| **Text Encoder (`5120`-dim)** | `Qwen3-VL-32B-Instruct` (`qwen3vl_32b_minimax_h3_int8_convrot.safetensors`, layer 50 / penultimate `hidden_states[-2]`, `dim=5120`) | Distilled `Qwen3-VL-4B` (`p-h3-image_text_encoder_int8_convrot.safetensors`, `4.7 GB`, loaded via `CLIPLoader(type="minimax")`) + FP32 `TextConnector`: concatenates 5 hidden layers `[13, 19, 25, 31, 36]` (`5 * 2560 = 12,800`), standardizes with learned `input_mean` / `input_std`, projects via bias-free `nn.Linear(12800, 5120, bias=False)` (`TextConnector.proj`), destandardizes to `output_mean` / `output_std` (`5120`), and replaces token 0 (`BOS`) with learned `sink_embedding` (`norm=15810.24`). **Teacher-compatible**: also accepts our 32B `MiniMaxH3EncoderLoader` directly, which our `h3_p_h3_image_*` graphs wire by default; the 4B encoder is wired by `h3_probe_p_h3_image_*_te4b_api.json` | `comfy/text_encoders/minimax.py:110-128, 172-250` (`TextConnector`, `PH3ImageTEModel`) |
| **Tokenizer** | `MiniMaxH3Tokenizer` (`Qwen3VLSDTokenizer` + 7 `MINIMAX_EXTRA_TOKENS` `151669..151675`) | `PH3ImageTokenizer` (`Qwen3VLSDTokenizer` **without** `MINIMAX_EXTRA_TOKENS`; `<d>`, `</d>`, `<|cutoff|>`, etc. are not registered) | `comfy/text_encoders/minimax.py:33-35, 254-258` |
| **Single-Frame VAE** | `MiniMaxH3VideoVAE` (`minimax_h3_video_vae_bf16.safetensors`) | `PH3ImageVAE(MiniMaxH3VideoVAE)` (`p-h3-image_vae_bf16.safetensors` / `p-h3-image_vae_int8_convrot.safetensors`): H3's 3D causal CNN encoder (`EncoderFCN3D`) with seeded diagonal-Gaussian sampling (`PH3_IMAGE_ENCODE_SEED = 42`), 24-channel `LATENTS_MEAN` / `LATENTS_STD` + ImageNet normalization, and `PH3ImageDecoder(ViT3DDecoder)` (`patch_size_t=1` and fixed temporal RoPE coordinate `PH3_IMAGE_FRAME_POSITION = 2.0 * (0.5 / 7) - 1.0`) | `comfy/ldm/minimax/vae.py:429-439, 1014-1033` |
| **Conditioning & Reference Stream** | `MiniMaxH3Conditioning` / `MiniMaxH3ReferenceConditioning` | [`MiniMaxH3PH3ImageConditioning`](../../ph3_image_nodes.py) (replaces core's `PH3ImageConditioning` at node `5`): creates both `conditioning` (with `_h3_span_masks` attached) and the single-frame AV latent (`_av_latent(canvas_w, canvas_h, 1, 2)`). On T2I graphs (`canvas="auto"` or `"explicit"`), `width=2912, height=2912` (`~8.48 MP`, `33,124` patch tokens). On Edit graphs (`1..8` images), `canvas="auto"` clamps `image_1` and the output canvas to `[4 MP, 8 MP]` (`4*1024^2..8*1024^2`) at `image_1`'s aspect ratio, clamps `image_2..image_8` to `[1 MP, 8 MP]`, resizes Qwen3-VL `vision_images` via `size_at_area` (`~1 MP`, both up and down), and rounds unnormalized VAE reference latents (`seed=42`) to `torch.float16` before `(latents - mean) / std` | [`ph3_image_nodes.py`](../../ph3_image_nodes.py) (`MiniMaxH3PH3ImageConditioning`) |
| **Prompt Upsampler** | External authoring with [`h3_system_prompt.md`](system_prompts/h3_system_prompt.md) | Omitted from all generated `workflows/image/` graphs (`prompt` is wired directly on node `5` `MiniMaxH3PH3ImageConditioning`, authored with [`h3_p_h3_image_system_prompt.md`](system_prompts/h3_p_h3_image_system_prompt.md)); [`MiniMaxH3PH3ImagePromptUpsampler`](../../ph3_image_nodes.py) (`enabled=False` by default, `lazy=True` on `clip`) remains registered as a standalone node | [`ph3_image_nodes.py`](../../ph3_image_nodes.py) |

## 2. Suboptimalities Fixed vs. PrunaAI's Reference ComfyUI Workflows

PrunaAI's upstream example workflows (`PrunaAI/P-H3-Image-Comfy`) had four defects that degraded quality or failed to run cleanly on ComfyUI core:

1. **Wrong Sigma Schedule (`ModelSamplingSD3(shift=1.0)` + `BasicScheduler("simple", 8)`)**:
   - Upstream's example JSONs wired `ModelSamplingSD3(shift=1.0)` + `BasicScheduler(scheduler="simple", steps=8)`, which produces a uniform linear schedule `[1.0, 0.875, 0.75, 0.625, 0.5, 0.375, 0.25, 0.125, 0.0]`.
   - `PrunaAI/P-H3-Image`'s actual `modular_model_index.json` (`coderef/diffusers/src/diffusers/modular_pipelines/p_h3_image/before_denoise.py:837-838`) uses the non-uniform 8-step distillation schedule `1.0, 0.984753, 0.967905, 0.951688, 0.925372, 0.881923, 0.810083, 0.528718, 0.0`, where 6 of the 8 steps are concentrated in the high-noise structural formation window `[1.0 -> 0.81]`.
   - Our workflows wire `MiniMaxH3SigmaShift(shift_video=1.0, shift_audio=1.0)` + `ManualSigmas(PH3_IMAGE_MANUAL_SIGMAS)`, guarded by [`bench/check_distill_settings.py`](../../bench/check_distill_settings.py) and [`bench/check_distill_grid.py`](../../bench/check_distill_grid.py).
2. **Removed the Broken T2I & Edit Prompt Upsampler Node Chains from Generated Workflows**:
   - Upstream's T2I workflow wired `ChatTemplate` (a custom node absent from ComfyUI core) or core's `TextGenerateLTX2Prompt` (which wraps prompts in Gemma `<start_of_turn>` tags and injects LTX-2's video system prompt).
   - Upstream's Edit workflow wired `TextEncodeQwenImageEditPlus` (`comfy_extras/nodes_qwen.py`), which accepts at most 3 images, downscales them to `384x384` (`147,456` px vs. upstream's `1,000,000` px), injects Qwen-Image-Edit's system prompt, and outputs `CONDITIONING` rather than calling `clip.generate`.
   - Per owner decision (2026-11-07), our generated `workflows/image/` workflows omit the prompt upsampler completely and wire `prompt` directly into node `5` (`MiniMaxH3PH3ImageConditioning`). [`MiniMaxH3PH3ImagePromptUpsampler`](../../ph3_image_nodes.py) remains registered in the pack as a standalone node implementing the exact upstream `prompt_upsampler.py` contract if ever wired manually.
3. **Dense Attention Floor (`ModelAttentionBackend(attention="comfy kitchen attention")`)**:
   - Upstream's workflows omitted `ModelAttentionBackend`. Our workflows wire `ModelAttentionBackend(attention="comfy kitchen attention")` (node `58`) for dense attention on single-frame graphs, matching the H3 video workflows (Sol-Attn is a 3D spatiotemporal video kernel and is exempt on single-frame graphs via `bench/check_attention_defaults.py::SOL_EXEMPT_STEMS`).
4. **Runtime `MiniMaxH3LoRABranch` (`rank=128` bf16), the 32B Encoder Default & 4B Distilled-Encoder Probes**:
   - Applying `h3/p-h3-image_lora_bf16.safetensors` (`rank=128`) onto `minimax_h3_fl2va_pruned_int8_convrot.safetensors` via [`MiniMaxH3LoRABranch`](../../lora_branch.py) preserves full bf16 LoRA precision without int8 merge requantization loss ([`docs/research/merge_requantisation.md`](../research/merge_requantisation.md)).
   - Because `TextConnector` was distilled to match `Qwen3-VL-32B-Instruct`'s `5120`-dim layer-50 representation, every `h3_p_h3_image_*` graph wires our stock 32B `MiniMaxH3EncoderLoader` (`qwen3vl_32b_minimax_h3_int8_convrot.safetensors`, node `2`) directly into `MiniMaxH3PH3ImageConditioning` (`workflows/build_workflows.py::build_ph3_image_api`, `teacher_te=True`). The owner chose 32B as the default on 2026-11-09 after reporting better quality from it: the image DiT's text path was trained against 32B-style rows that the 4B `TextConnector` only approximates, and the pack's control vectors are built from 32B rows. `h3_probe_p_h3_image_t2i_te4b_api.json` and `h3_probe_p_h3_image_edit_te4b_api.json` wire the release's distilled 4B encoder (core `CLIPLoader`, `type="minimax"`, `p-h3-image_text_encoder_int8_convrot.safetensors`) for a same-seed comparison against that default.
5. **Replaced ComfyUI Core's `PH3ImageConditioning` with [`MiniMaxH3PH3ImageConditioning`](../../ph3_image_nodes.py) (1:1 `diffusers` & `MiniMax-H3` Parity)**:
   - Across the reference engines (`diffusers` `coderef/diffusers/src/diffusers/modular_pipelines/p_h3_image/{before_encoder,encoders,before_denoise}.py` and `MiniMax-H3` `coderef/MiniMax-H3/Ref2VA/video_vae/klvae.py:910`; `sglang` and `vllm-omni` implement `MiniMax-H3` video only), ComfyUI core's `PH3ImageConditioning` (`comfy_extras/nodes_minimax_h3.py:668-731`) and `PH3ImageVAE.encode` (`comfy/ldm/minimax/vae.py:1022-1029`) have four gaps that `MiniMaxH3PH3ImageConditioning` fixes without patching ComfyUI core:
     1. **Area-range clamping (`size_in_area_range`) vs. downscale-only (`_size_within_area`)**: Core's `_size_within_area` (`comfy_extras/nodes_minimax_h3.py:668-671`) uses `scale = min(1.0, math.sqrt(pixels / (width * height)))` (downscale only), leaving a `1024x1024` `image_1` at `1 MP` instead of the `4..8 MP` (`4*1024^2..8*1024^2`) canvas range `P-H3-Image` was distilled for. `MiniMaxH3PH3ImageConditioning` (`resolve_ph3_image_geometry`) matches `coderef/diffusers/src/diffusers/modular_pipelines/p_h3_image/before_encoder.py:60-68, 97-100, 163-179`: under `canvas="auto"` (default), `image_1` and the output canvas are clamped to `[4 MP, 8 MP]` (`1024x1024` -> `2048x2048`), secondary references `image_2..image_8` are clamped to `[1 MP, 8 MP]`, in-range multiples of `32` are kept untouched, and Qwen3-VL `vision_images` are resized via `size_at_area` (`~1 MP`, both up and down, keeping native size when already a multiple of `32` within 20%).
     2. **Decoupled explicit canvas (`canvas="explicit"`) vs. coupled reference area**: In core's `PH3ImageConditioning` (`comfy_extras/nodes_minimax_h3.py:714, 720`), passing non-zero `width, height` sets `area = width * height` for VAE reference scaling as well as the output canvas. In `diffusers` (`coderef/diffusers/src/diffusers/modular_pipelines/p_h3_image/before_encoder.py:80, 164-166`) and `MiniMaxH3PH3ImageConditioning`, setting `canvas="explicit"` changes the output canvas (`round_canvas(width, height)`) while keeping edit reference images clamped to `[1 MP, 8 MP]`.
     3. **Float16 conditioning-latent rounding (`coderef/diffusers/src/diffusers/modular_pipelines/p_h3_image/encoders.py:64-65`, `coderef/MiniMax-H3/Ref2VA/video_vae/klvae.py:910`) without mutating `first_stage_model` buffers**: Both `diffusers` (`latents = latents.to(torch.float16).float().cpu(); return (latents - latents_mean) / latents_std`) and `MiniMax-H3` (`coderef/MiniMax-H3/Ref2VA/video_vae/klvae.py:910`) round the unnormalized seeded posterior sample (`seed=42`) to `torch.float16` (~11-bit mantissa) before normalizing `(latents - latents_mean) / latents_std`; core's `PH3ImageVAE.encode` (`comfy/ldm/minimax/vae.py:1026-1028`) keeps `latents` in `float32`. `MiniMaxH3PH3ImageConditioning` (`_encode_ph3_image_condition`) calls `z = vae.encode(image_tensor)` first without mutating `vae.first_stage_model.latents_mean` or `latents_std` (mutating those buffers before `vae.encode()` caused `ModelPatcherDynamic.load()` at `comfy/model_patcher.py:2114-2120` to snapshot `0` and `1` into `vae.patcher.backup_buffers`, which `restore_loaded_backups()` then restored on `VAEDecode`, decoding without denormalization and producing a 16x16 ViT patch grid), recovers `unnorm = z.float() * std_t + mean_t`, rounds `unnorm.to(torch.float16).float()`, and normalizes `((rounded - mean_t) / std_t).to(dtype=z.dtype)`.
     4. **Strict 8-image cap (`MAX_EDIT_IMAGES = 8`, `image_1..image_8`) and `_h3_span_masks`**: Matches `coderef/diffusers/src/diffusers/modular_pipelines/p_h3_image/before_encoder.py:46, 158` (core's `PH3ImageConditioning` exposed 9 slots) and attaches `_h3_span_masks` (`h3_spans.py::attach_span_masks`) so post-refiner control vectors work seamlessly on `MiniMaxH3PH3ImageConditioning`.
