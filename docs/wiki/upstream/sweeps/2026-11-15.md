## What is worth the owner's attention, in order

1. **H3 video ref2va stills: sglang stopped upscaling small stills by default, as a speed change.** *Checked by
   hand, including the PR body.* The standing comparison, the case each way and what a change would involve are on
   [`../topics/reference_sizing.md`](../topics/reference_sizing.md). *Corrected the same day: this item first read the
   change as an adopt-upstream default move.* This is the video pipeline (`MiniMaxH3SamplingParams`); MiniMax-H3-Image has its
   own bounds (Qwen copy 1024, VAE copy 1024 to 2048) and did not change.
   - **Before 2026-11-05**, sglang's default was `diffusers` mode: every still is scaled to a 2048 short edge,
     including upscaling small ones. This pack's `size_policy=max` with `allow_upscale=True` copies that
     (`../../core/h3_references.md`, the mode list).
   - **Now** `MINIMAX_H3_DEFAULT_REFERENCE_RESIZE_MODE = "max"` (`92a6910ef2`, #47907;
     `coderef/sglang/python/sglang/multimodal_gen/runtime/pipelines_core/stages/model_specific_stages/minimax_h3/constants.py`).
     `max` only shrinks stills whose short edge is past 2048. FastH3 Omni keeps `diffusers`, marked "not validated
     for this checkpoint".
   - **Why it changed:** the PR is labelled `[Perf]`. An sglang ref2va workload was slower than vllm-omni, and
     upscaling small stills adds reference tokens on every step. The PR deleted the comment that called `diffusers`
     "the original Diffusers and SGLang reference-image behavior" and said it "should remain the compatibility
     default unless a checkpoint specifies another preprocessing policy".
   - **Its own quality table** (VBench proxies, small-reference cases, in the PR body) has `max` slightly below
     `diffusers` on nearly every row, reference-subject similarity included. Its author calls the review informal
     and not a quality-equivalence study.
   - **The other engines:**
     - vllm-omni keeps each still's own size, rounded to 32, and never upscales
       (`coderef/vllm-omni/vllm_omni/model_executor/models/minimax_h3/preprocessing.py::resolve_minimax_h3_reference_image_shape`);
     - core never upscales (`comfy_extras/nodes_minimax_h3.py`, the `ref_image_size` tooltip);
     - diffusers and DiffSynth still scale to 2048.
   - **What it touches here:** updated later on 2026-11-15 (owner decision after inspecting sglang PR #47907): `reference_conditioning.py` (`MiniMaxH3AppendRefImage.allow_upscale` default `True -> False`) and `workflows/build_workflows.py` (`ref_upscale=False` default on non-instrument video graphs; see [`../topics/reference_sizing.md`](../topics/reference_sizing.md)).
   - **Reading:** sglang's change trades a little identity for latency, and the owner's renders are judged on
     quality. Nothing here argues for moving our default. The 2026-09-11 rule is about defaults the vendor's path
     and core agree on for their own reasons, and this one was moved for speed. The token cost of upscaling is
     already priced in `../../core/h3_references.md` (measured 2026-08-13).
   - Side effect, the agent's reasoning: sglang's Pika inherits `max`, so it no longer upscales small stills, which
     Pika's own `buckets.yaml` does.
2. **MiniMax-H3-Image's Euler step: both ranked engines use the float32 velocity form; our graphs use stock `euler`.**
   *Checked by hand.* Standing page: [`../topics/h3_image_sampling_step.md`](../topics/h3_image_sampling_step.md).
   - sglang's image loop steps `target_rows + sigma_deltas[step] * v.float()` (`.../minimax_h3/denoise_loop.py`,
     `minimax_h3_image_denoise_loop`).
   - diffusers added `euler_update_form="velocity"` for H3-Image (`875373ac7`, #15230;
     `coderef/diffusers/src/diffusers/schedulers/scheduling_minimax_h3.py`). Its docstring claims the heads were
     distilled with that form, and that the bf16 model amplifies the last-bit difference into a visibly different
     image. That claim is theirs and was not tested here.
   - Core's `euler` reaches the same update through `x0` and `d`, with different roundings.
   - Both engines also derive sigmas as `1 - (1 - sigma)` in float32, which moves the sigmas below 0.5 by one ulp
     (diffusers `modular_pipelines/minimax_h3_image/before_denoise.py`; DiffSynth
     `set_timesteps_minimax_h3_image`). The values were not compared with `h3_config.H3_IMAGE_MANUAL_SIGMAS`.
   - A one-seed A/B with a velocity-form sampler would settle whether this shows.
3. **Core PR #17715 (open) would run the token refiner on every step.** It removes `preprocess_text_embeds` from
   `model_base.MiniMaxH3.extra_conds` and casts the refiner's q/k to `v.dtype`. If it merges, the `lora_branch.py`
   tooltip ("token_refiner runs once before step 0") and `nodes.py`'s `patch_token_refiner` assumption both need a
   re-read, and so does the control-vector seam on post-refiner rows. Also on [`../horizon.md`](../horizon.md).
4. **Masked lane: two new public approaches to the same task.**
   - Viggle Remake (Hugging Face `Viggle/Viggle-Remake`, created 2026-10-22, updated 2026-11-07; the repo listing
     was checked by hand) has two LoRAs on the base transformer, `swap` and `edit`. Its inputs are one to four
     painted `<Picture N>` frames, a required six-section prompt, and windows inside the owner's 90–345 range. It
     ships `PROMPTING.md` and `COMFYUI.md`.
   - vllm-omni's character-replacement skill (`b8f128171`, #9194;
     `coderef/vllm-omni/.agents/skills/vllm-omni-h3-character-replacement/`) uses reference conditioning only, with no
     pixel lock, the akatz-ai Character Swap LoRA, and six-section `<Subject N>` prompts.
   - The skill's own unmeasured claims: segments of about five seconds hold identity better, and a segment can be
     generated backward by reversing the source.
   - Both are research to read against `docs/wiki/masked_v2v.md`, not defaults.
5. **Reference release, upstream versions.**
   - vllm-omni #9762 (open, NPU) conditions on a ref2va video reference for only the first k steps, then switches to
     an image-only layout. That is `MiniMaxH3ReleaseReferences`' `video_end_percent` done by changing the layout.
   - vllm-omni #9689 (open) is opt-in reference isolation, where reference queries read only reference K/V. Its
     author says it is not lossless. It is close to `MiniMaxH3FrozenVideoCache`.
6. **Encoder (shared by every model the pack runs).** Neither item below is checked against core.
   - sglang rebuilds the Qwen3-VL vision RoPE table on the GPU for image releases only. A table built on the CPU
     computes `pow` differently, and video releases keep the CPU table their references were made with (`6be0d75ae0`,
     #49574; `runtime/pipelines/minimax_h3_pipeline.py`, checked by hand). Where core builds that table was not
     checked.
   - vllm-omni added `text_encoder_cudnn_sdp`. cuDNN SDPA is on by default during encode, and turning it off makes
     the same seed give the same image across restarts (`coderef/vllm-omni/vllm_omni/diffusion/models/minimax_h3/encoder.py::cudnn_sdp`,
     checked by hand). Whether core's encoder attention reaches cuDNN SDPA was not checked.
7. **Pika numerics in sglang** (`f98e9611bc`, #47468; checked by hand).
   - The Pika pipeline sets `torch.set_float32_matmul_precision("highest")` and casts the release's fp32 LoRA factors
     to bf16, still unmerged.
   - `MiniMaxH3LoRABranch` already casts its factors to the compute dtype (`lora_branch.py`, the cast to `like.dtype`),
     so it aligns.
   - Condition noise is drawn from a generator seeded `noise_seed + 7919`. LightX2V (`1053bb0a`) and vllm-omni's draft
     #9777 use the same seed offsets (initial `seed`, re-noise `seed + 1`, condition `seed + 7919`). That is three
     engines agreeing on Pika's RNG streams, which matters only for seed-exact parity with Pika's release.
8. **Long clips in vllm-omni's ComfyUI app** (`b8f128171`; checked by hand). The defaults are
   `continuation_window_frames=311`, step 17, with overlap 39 (`coderef/vllm-omni/apps/ComfyUI-vLLM-Omni/comfyui_vllm_omni/nodes.py`, the H3 params node).
   311 is off `h3_rules.on_both_clocks`. Our chain rule stands; this is where theirs differs.
