# Upstream read, 2026-11-17: MiniMax-H3-Image inference

A scoped read, not a full sweep. It covers only MiniMax-H3-Image inference: text to image and edit, every stage from
loading to the decoded picture. It read five upstreams (sglang, vllm-omni, diffusers, DiffSynth-Studio,
LightX2V), ComfyUI core and this pack's shipped image graphs. The owner asked for it: what each implementation does
differently, and whether text to image gives the text encoder vision tokens.

The standing picture it produced is [`../topics/h3_image_pipeline.md`](../topics/h3_image_pipeline.md). Three pages
were updated with it: [`../topics/h3_image_sampling_step.md`](../topics/h3_image_sampling_step.md),
[`../topics/qwen3vl_encoder.md`](../topics/qwen3vl_encoder.md) and the engine and periphery pages.

**How it was read:**
- **The clones.** Each was fast-forwarded to its GitHub tip first (`git pull --ff-only`). sglang and diffusers
  moved; the others were already at their tips.
- **The revisions are not repeated here** ([`../index.md`](../index.md)), and [`../watchlist.json`](../watchlist.json)
  was not moved. Only the H3-Image paths of each entry were read, not each entry's whole range.
- **The agents.** Five read-only subagents, one per upstream, answered the same eight-stage brief: loading, the
  text-to-image encode, the edit encode, the canvas, references, sampling, decode, and anything else.
- **Core and the pack** were read by hand.
- **"By hand"** below marks a line checked against the cited file this session. Everything else is an agent's
  reading. Nothing was rendered.

## What is worth the owner's attention, in order

1. **Text to image gives the text encoder no vision tokens in any implementation, and the pack's graph sends the
   same tokens.** *By hand* in sglang, vllm-omni, diffusers, DiffSynth and core; LightX2V is the agent's reading.
   - No implementation adds a picture, a vision block, a `Picture` label, a template or special tokens when there
     are no references.
   - The pack's `h3_image_t2i` graphs run core's `MiniMaxH3ImageConditioning` with no pictures, which tokenizes the
     prompt alone (`comfy/text_encoders/minimax.py::MiniMaxH3Tokenizer.tokenize_with_weights`).
   - Nothing to change. The community "neutral vision patches for t2i" idea gives the model an input no engine
     gives it ([`../periphery.md`](../periphery.md)).
2. **The pack's edit graph matches the ranked engines on reference preparation and on draw order.** *By hand.*
   - The 2026-11-13 rows of [`../../image/h3_image.md`](../../image/h3_image.md) ("Edit references, point by point")
     hold at today's tips: the crop, the posterior drawn from the request's seed, the fp16 rounding, the fp32 encode.
   - sglang and vllm-omni draw target, anchors, posteriors (sglang's `.../minimax_h3/image_noise.py` header;
     vllm-omni's `pipeline_minimax_h3_image.py`, the comment at the top of `forward`). That is
     `reference_encode.py::sample_release_references`'s order.
   - **What still differs from every engine:**
     - the anchor noise, core's stream restarted per reference (`comfy/ldm/minimax/model.py::_cond_video_rows`);
     - the Euler form (stock `euler`, tested 2026-11-15);
     - the owner's choices of size, DiT file, attention and decoder.
3. **The sigma grid is the same bit for bit in every implementation.** *By the commands below.*
   - The release's `pdd_config.json` lists exactly `H3_IMAGE_MANUAL_SIGMAS`.
   - The engines' float32 `1 - sigma` round trip leaves every value of it unchanged.
   - [`../topics/h3_image_sampling_step.md`](../topics/h3_image_sampling_step.md) used to say the round trip moves
     the sigmas below 0.5 by one ulp; it now says it can, and does not on this grid.
4. **Prompt edges and empty prompts.** *By hand.*
   - **Edges:** no engine strips a prompt, and neither does core. The pack strips both ends in its own nodes
     (`h3_rules.py::normalize_prompt`), so its edit path strips and its text-to-image path does not. The shipped
     prompts have no edge whitespace, and the heylook expander strips its reply (`parse_expander_reply`), so this is
     reached only by text typed into the graph.
   - **Empty prompts:** every engine refuses one except DiffSynth, which encodes `" "`. Core encodes one pad token
     and runs, so the pack's text-to-image graph accepts an empty prompt.
5. **A Qwen copy whose short edge already sits on the bound,** with its long edge off the 32 px grid, is resized
   differently in each case. *By hand.*
   - **The engines** pass it untouched to the HF processor. The release's `processor/preprocessor_config.json` names
     `Qwen2VLImageProcessorFast` with no resample, and the class default is bicubic (transformers in ComfyUI's
     venv, `image_processing_qwen2_vl`).
   - **Core** resamples it with Lanczos to the grid first.
   - **The pack** passes it untouched to core's preprocessor, which resizes it with bilinear
     (`comfy/text_encoders/qwen_vl.py::process_qwen2vl_images`).
   - So both differ from the engines, each in its own way. Not rendered.
6. **The delivered bytes follow the engines' path.** *By the command below.*
   - The engines cut the decode to 8 bits by truncation and resize that 8-bit picture with PIL Lanczos; diffusers
     calls the truncation the released pipeline's.
   - `MiniMaxH3ImageDownscale` does the same, and ComfyUI's `PreviewImage` / `SaveImage` conversion gives back
     exactly those bytes.
7. **The periphery's outliers.**
   - **DiffSynth's examples** load every model at bf16, the fp32 parts included (*by hand* for the example's
     `torch_dtype`; the rest the agent's reading).
   - **LightX2V** draws posteriors first, as diffusers does, and its shipped configs run the DiT on `sage_attn2`
     with an AdaLN cache on (*by hand*: `configs/minimax_h3_image/*.json`).

## Commands run

All from the pack's root with ComfyUI's venv Python (`$COMFY/.venv/bin/python`), with `h3.env` loaded.

- **The sigma round trip.** It prints `same` for all seven values:

  ```bash
  "$COMFY/.venv/bin/python" -I -c "
  import torch
  s=[1.0,0.9675236940383911,0.8875485062599182,0.75,0.5327739119529724,0.23200887441635132,0.0]
  a=torch.tensor(s,dtype=torch.float32); t=1.0-a[:-1]; b=torch.cat((1.0-t,torch.zeros(1)))
  print(['same' if x==y else 'DIFF' for x,y in zip(a.tolist(),b.tolist())])"
  ```

- **The release's grid and processor.** `$H3_MODEL_STORE/MiniMaxAI_MiniMax-H3-Image/pdd_config.json` was read against
  `workflows/h3_config.py::H3_IMAGE_MANUAL_SIGMAS`, and they are equal. Its `processor/preprocessor_config.json`
  was compared with `vendor_config/preprocessor_config.json`, and they are equal:

  ```bash
  diff <(python3 -m json.tool "$H3_MODEL_STORE/MiniMaxAI_MiniMax-H3-Image/processor/preprocessor_config.json") \
       <(python3 -m json.tool vendor_config/preprocessor_config.json)
  ```

- **The 8-bit round trip.** Every byte value, divided by 255 as `MiniMaxH3ImageDownscale` returns it, then put
  through ComfyUI's save conversion (`nodes.py`, `np.clip(255. * i, 0, 255).astype(np.uint8)`), comes back
  unchanged. The mismatch count printed is zero:

  ```bash
  "$COMFY/.venv/bin/python" -I -c "
  import torch, numpy as np
  k=torch.arange(256,dtype=torch.uint8); i=k.float().div(255.0).numpy()
  print(int((np.clip(255.*i,0,255).astype(np.uint8)!=k.numpy()).sum()))"
  ```

- `"$COMFY/.venv/bin/python" bench/check_reference_encode.py`: all cases passed.

## The agents' reading only

- Each engine's list of fp32 islands in the DiT.
- How each encoder drops its layers past 50 and its final norm.
- How mRoPE is built in sglang, DiffSynth and LightX2V (HF-style `get_rope_index`).
- Decode internals: sglang's tile batching, vllm-omni's CUDA-graph tile replay, and diffusers' blend of a tile
  against its neighbours' raw decodes (which the 2026-11-14 VAE inspection had already read).
- The vision tower's input dtype in sglang and vllm-omni, and vllm-omni's separate Q, K and V GEMMs.
- sglang's conditioning cache and the absence of a reference cap in its edit profile.
- vllm-omni's XPU recipe on edit prompts.
- LightX2V's refusals (LoRA, quantized DiT), its empty-prompt refusal and its AdaLN cache internals.
- That DiffSynth's latent statistics end up in bf16, which the agent inferred from `Module.to`.
- diffusers' note that `decoder.proj_in` is not kept in fp32 under a bf16 load, which the agent inferred from its
  loader's name matching.
