## 2026-11-07

- **Fixed `PH3ImageVAE` `ModelPatcherDynamic.backup_buffers` poisoning in `ph3_image_nodes.py::_encode_ph3_image_condition` and removed `MiniMaxH3PH3ImagePromptUpsampler` from all generated `workflows/image/` workflows**:
  1. **Root cause & fix for 16x16 blocky/blurry `VAEDecode` output (`ph3_image_nodes.py:337-364`)**: `_encode_ph3_image_condition` previously mutated `fsm.latents_mean = 0` and `fsm.latents_std = 1` inside a `try ... finally` block around `vae.encode(image_tensor)`. Because `vae.encode` calls `model_management.load_models_gpu([self.patcher])` -> `ModelPatcherDynamic.load()` (`comfy/model_patcher.py:2114-2120`), which snapshots `self.model.named_buffers()` into `self.backup_buffers` on first load, `vae.patcher.backup_buffers["latents_mean"]` and `["latents_std"]` cached the `0` and `1` tensors. When `VAEDecode` subsequently ran after the DiT, `ModelPatcherDynamic.load()` called `restore_loaded_backups()` (`comfy/model_patcher.py:1939-1940, 1960`), overwriting `fsm.latents_mean` and `fsm.latents_std` back to `0` and `1` and causing `PH3ImageVAE.decode` (`z * self.latents_std + self.latents_mean`) to decode without denormalizing the latent. Fixed `_encode_ph3_image_condition` so it calls `z = vae.encode(image_tensor)` first without ever mutating `fsm.latents_mean` or `fsm.latents_std`, and then recovers `unnorm = z.float() * std_t + mean_t` read-only before `.to(torch.float16).float()` rounding and `(rounded - mean_t) / std_t`.
