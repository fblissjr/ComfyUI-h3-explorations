# Designing an experiment in this repo

Nothing here is the process. Each line names the file that is, in the order a
design goes through them.

1. **What would count as an answer.** `docs/roadmap.md` ("The right rail: what
   good means", then "The regime question"). `docs/open_experiments.md` says
   what is deliberately unmeasured and the blocker for each; an experiment
   that would not move a default, a doc claim, or code is not one.
   `docs/evidence.md` says which numbers must not be built on.

2. **Which regime, which canvas, which seeds.** Ask the owner which canvases
   and aspect ratios before any bench, and default to ones cheaper than 16:9
   (a standing instruction). Base model at 16 steps and the 4-6 step students
   are different regimes; `docs/roadmap.md`'s regime section says what
   transfers between them. A perceptual claim needs a distribution of seeds,
   never a pair (`CLAUDE.md`).

3. **How an arm becomes a graph.** Every graph is generated by
   `workflows/build_workflows.py` from constants in `workflows/h3_config.py`;
   a `workflows/*.json` is never hand-edited. A probe is one row that differs
   from a named twin in exactly one thing, with a `_probe_note` that names the
   twin, the variable, what to look at and what to expect -- read an existing
   probe row before writing one. Sol-Attn is on in every video graph unless the
   graph is one of the exceptions `CLAUDE.md` lists and
   `bench/check_attention_defaults.py` exempts by mechanism. A setting that a
   vendor row does not attest (a LoRA step count the check would refuse, a
   file with no documented shift) runs as a `bench/run_graph_arms.py --set`
   patch, not as a shipped row.

4. **How a prompt is written.** `docs/prompting.md` owns this end to end, and
   the `h3-prompt` sibling skill routes into it by task. **This step used to
   name `internal/2026-8-20-system-prompts/`, which does not exist** -- a dead
   pointer to a gitignored directory, corrected 2026-09-01. A t2v prompt
   is the three-field layout; a reference prompt is the six-field layout whose
   `<Picture N>` labels must name exactly the references the graph wires
   (`bench/check_ref_prompt_labels.py` enforces that, and `_ref_prompt()` in
   the generator is how the shipped reference prompts are built).
   `docs/comfy_notes.md` holds the prompting notes and the `node_id` rule.

5. **Before the card.** `bench/preflight_graph.py <graph>` grades the prompt
   against the guide's mechanical rules and prices the packed sequence; run
   it on any new or hand-built graph. `bench/check_distill_settings.py` grades
   every LoRA row's shift and steps against the vendor's own table. Regenerate
   and run the fast checks `docs/checks.md` indexes; a new bench tool gets one
   throwaway invocation read end to end before any batch, and an instrument
   gets a deliberate-violation test.

6. **Running and judging.** `h3-ab-session` (the sibling skill) and
   `docs/eval_comparison.md` section 3 own everything from the first render to
   the verdict record.

If a step here disagrees with the file it names, the file is right and this
skill is stale.
